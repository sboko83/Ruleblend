# Участие в разработке

[English version](../../CONTRIBUTING.md)

Используйте шаблоны issue для воспроизводимых ошибок и предложений. Изменения форматов файлов,
хранилища и интеграций с ассистентами обсуждаются до реализации. Соблюдайте
[правила поведения](../../CODE_OF_CONDUCT.md); об уязвимостях сообщайте по [SECURITY](SECURITY.md).

## Сборка и тесты

Запускайте команды из корня репозитория. Нужны Git, JDK 21 для демона Gradle и Python 3.12+.
Gradle скачивает JDK 17 для приложения и тестов, если он отсутствует. Первая сборка требует
интернета. Для сборки на macOS также нужны Xcode command-line tools и Swift toolchain, способный
собрать [помощник перевода](../../tools/translate-helper/Package.swift).

На macOS:

```sh
./gradlew :app:run
./gradlew -PwarningsAsErrors=true :core:allTests :mcp:allTests :app:allTests :app:compileUiE2eKotlinJvm
./gradlew :app:packageDistributionForCurrentOS
```

На Windows выберите JDK 21 через `JAVA_HOME` или Gradle JVM в IDE:

```powershell
.\gradlew.bat :app:run
.\gradlew.bat -PwarningsAsErrors=true :core:allTests :mcp:allTests :app:allTests :app:compileUiE2eKotlinJvm
.\gradlew.bat :app:packageDistributionForCurrentOS
```

Контракты без UI проверяются Python 3 на обеих системах (`python3` на macOS, `python` на Windows):

```sh
python3 -B -m unittest discover -s tools -p 'test_*.py'
python3 -B tools/mcp_contract.py
```

Проверки CI заданы в [.github/workflows/ci.yml](../../.github/workflows/ci.yml), включая покрытие
лицензий зависимостей и проверки упакованного приложения. Модульные тесты не запускают графические
наборы и нативные проверки перевода macOS. Для изменений UI запускайте подходящие сценарии из
[UI_E2E](UI_E2E.md) и явно указывайте непройденные проверки.

## Гарантии записи файлов

- Сохраняйте всё вне управляемых Ruleblend областей. Исключения требуют вызванного пользователем
  **Save to library** с включённой заменой либо явно подтверждённого удаления сторонней папки
  скилла или записи MCP; см. [архитектуру](ARCHITECTURE.md).
- Записывайте пользовательские файлы атомарно через временный файл и переименование. Сохраняйте
  локальные правки и сообщайте о конфликтах вместо молчаливой перезаписи; одной атомарности недостаточно
  для защиты от потери обновлений.
- Добавляйте модульные тесты при изменении парсинга маркеров и слияния при импорте. Проверяйте
  разрушительные операции и конфликты на временных фикстурах, а не реальных настройках ассистентов.
- В режиме `--mcp` stdout принадлежит только протоколу; диагностика направляется в stderr.

## Pull request

Ограничивайте изменение одной задачей. Опишите проблему пользователя, итоговое поведение и проверки.
Для изменений UI приложите снимок с тестовыми данными. Не прикладывайте реальные библиотеки, секреты,
URL приватных репозиториев и конфигурации ассистентов без удаления личных данных.

`core` не зависит от `mcp` и `app`, `mcp` не зависит от `app`.
Перед архитектурными изменениями читайте [архитектуру](ARCHITECTURE.md) и обновляйте затронутые решения.
Обновляйте английскую документацию и русский перевод вместе. Изменению поведения соответствует одна
английская запись в `[Unreleased]` в [CHANGELOG](../../CHANGELOG.md); рефакторинг без смены поведения
не требует записи.

Код, комментарии и конфигурация — на английском. В публичном репозитории сообщения коммитов —
на английском: заголовок начинается с глагола в повелительном наклонении, тело объясняет изменение
и причину. Для изменений поставляемого кода или ресурсов увеличивайте `appBuild` на один в
`app/build.gradle.kts`. Не меняйте `appVersion` без согласования с владельцем. Версии инструкции
ассистента и регистрации коннектора меняются только при изменении устанавливаемого содержимого;
см. [архитектуру](ARCHITECTURE.md#mcp-сервер).

Вклад распространяется по [лицензии проекта](../../LICENSE); сторонние материалы сохраняют
лицензию и атрибуцию. Перед добавлением зависимостей или ресурсов читайте [THIRD-PARTY](../../THIRD-PARTY.md).
