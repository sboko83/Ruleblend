# Архитектура

[English version](../ARCHITECTURE.md)

Устройство Ruleblend. История изменений — в [CHANGELOG.md](../../CHANGELOG.md),
открытая работа — в [ROADMAP.md](ROADMAP.md).

<a id="purpose"></a>
## Назначение

Desktop-приложение организует библиотеку блоков инструкций для AI-агентов разработки
и устанавливает их в глобальные настройки агентов или каталоги проектов.
Решения о публичном распространении — в [RELEASING](RELEASING.md).

<a id="modules"></a>
## Модули

Kotlin Multiplatform, Gradle 9.7 и современный KMP DSL. Сейчас используются только
JVM-цели; Android Gradle Plugin не применяется.

```
ruleblend/
├── core/   # models, storage, git, marker parser, agent adapters, translation
├── mcp/    # MCP server facade over core (stdio) + MCP-config connectors + MCP-block installers
├── app/    # Compose Desktop UI over core; `--mcp` runs the mcp server instead
└── tools/translate-helper/  # Swift helper over the macOS Translation framework, shipped in the bundle
```

Зависимости направлены в одну сторону: `app → mcp → core`. `core` не знает об UI;
будущий CLI станет ещё одним фасадом, как уже существующий MCP-сервер. JGit привязывает
`core` к JVM; это допустимо, поскольку все desktop-цели используют JVM.

На macOS стандартная Gradle-задача `run` запускает созданный `.app`, а не обычный
`JavaExec`: LaunchServices берёт идентичность для Dock и переключателя приложений
из bundle. Прямой запуск JVM может отображаться как `java` даже с `-Xdock:name`.

<a id="use-cases"></a>
### Сценарии использования

`core/usecase` определяет действия фасада, а нижележащие сервисы — операции записи:

| Сценарий | Ответственность |
|---|---|
| `InstallObject` / `RemoveObject` | Установка или удаление по парам цель × объект, с результатом для каждой пары |
| `InstallPolicy` | Единый ответ, разрешена ли запись в это место и почему |
| `AcceptLocalChange` | Принятие правки из файла цели как следующей версии в библиотеке |
| `MutateLibrary` | Все записи библиотеки, каждая одной транзакцией |
| `ImportLibrary` | Импорт/экспорт архивов, импорт скиллов и субагентов из Git |

Compose-модели и MCP-сервер преобразуют ввод в команду и показывают типизированный
результат. Решения принимает этот слой: отдельные проверки области правила,
возможностей цели и локальных правок в Place, массовой установке Library и MCP
уже приводили к расхождениям для изменённой MCP-записи. Единая реализация защищает
от записи не в тот файл и потери пользовательских изменений.

Удаление симметрично установке: изменённая после записи Ruleblend копия сохраняется
и попадает в отчёт независимо от типа объекта и фасада. Отбрасывание такой правки —
решение по конкретному файлу в Place, а не побочный эффект удаления набора.

`core` не зависит от `mcp`: запись MCP проходит через интерфейс `McpBlockService`,
который реализует `McpInstallService` модуля `mcp`. Фасад без поддержки MCP передаёт
`McpBlockService.None`.

<a id="windows-distribution"></a>
## Распространение на Windows

- MSI устанавливается для текущего пользователя в `%LOCALAPPDATA%/Ruleblend`,
  создаёт ярлыки рабочего стола и меню «Пуск». Постоянный путь сохраняет работоспособность
  зарегистрированных MCP-команд после обновления.
- UpgradeCode постоянен; версия MSI — `<major>.<minor>.<appBuild>` из `appVersion`,
  например `0.5.240`. UI показывает полный `appVersion` и отдельный build.
  `appBuild` растёт между patch-релизами; пределы трёх полей MSI — 255, 255 и 65535.
  Четвёртое поле Windows Installer игнорирует, поэтому оно не обеспечит обновление только по build.
- MSI упаковывает подготовленный образ приложения, сохраняя UTF-8 manifest launcher.
  Runtime включает дополнительные модули, найденные анализом зависимостей; внешний Java не нужен.
- Установщик владеет только файлами приложения и ярлыками. Библиотека, состояние
  `~/.ruleblend` и конфигурации ассистентов находятся снаружи и сохраняются при обновлении и удалении.

<a id="data-model"></a>
## Модель данных

- **Термины:** `agent` — внешний инструмент (Claude Code, Codex, Pi, Kimi Code или ZCode);
  `subagent` — элемент библиотеки, описывающий поведение для этого инструмента.
  В заголовках UI первый называется AI-ассистентом; сохранённые имена и MCP-контракты используют `agent`.
- **`Block`:** `id` (slug и имя файла), `name`, `description`, целочисленный `version`,
  `type`, `content`. Изменение устанавливаемого определения повышает версию.
  Новый блок с пустым телом начинается с 0; первое сохранённое тело получает v1.
  У `subagent` есть `variants` с полями по id ассистента; их изменение тоже создаёт версию
  (см. [форматы субагентов](#subagent-formats)).
- **Типы:** `rule` (Markdown), `mcp` (канонический JSON, см. [MCP-блоки](#mcp-blocks)),
  `subagent` (Markdown). Скиллы хранятся отдельно, каталогами: скрипты, справочные материалы
  и ресурсы должны оставаться вместе с `SKILL.md`.
- **`Skill`:** стабильный локальный id, имя, описание, непрозрачная версия репозитория,
  содержимое `SKILL.md` и необязательное происхождение из Git — URL, точный SHA и путь
  относительно репозитория. Импорт неизменяем; редактируемая копия переносит происхождение
  в `forkedFrom`, получает имя с `-changed` и локальную числовую версию.
  Локальные скиллы можно создавать напрямую; сохранение синхронизирует структурированные
  имя и описание с frontmatter `SKILL.md`, сохраняя инструкции и дополнительные ключи.
- **Область правила:** глобальная или один проект. Это не поле `Block`: абсолютный путь
  проекта — состояние машины в `config.json`, по id блока. Смена области не повышает
  версию содержимого и не переносит локальный путь checkout в Git переносимой библиотеки.
- **`Group`:** `id`, `name`, `description`, упорядоченные `blockIds`, `skillIds`, `version`.
  Изменение любого списка участников повышает версию.
- **`Profile`:** переносимый версионируемый режим проекта: упорядоченные id прямых правил,
  MCP-блоков, скиллов и субагентов плюс id плоских групп. Включает группы, но не профили.
  Изменение участников повышает версию; изменение только имени или описания — нет.
- **Служебная группа `all`:** автоматически содержит все id блоков и скиллов,
  пересчитывается при загрузке и изменении библиотеки. Профили в неё не входят.
  Закреплена первой, недоступна для редактирования и удаления, исключена из импорта/экспорта:
  это локально вычисляемое состояние, а не переносимое содержимое.

<a id="storage"></a>
## Хранение

Всё находится в `~/.ruleblend/`; путь библиотеки настраивается.

Если при первом запуске после переименования `~/.ruleblend/` отсутствует, а `~/.kitbash/`
существует, старый home полностью копируется через соседний staging-каталог и публикуется
атомарным rename. Старый home остаётся для отката; сгенерированные launchers и lock процесса
не переносятся. Если существуют оба home, используется новый, без слияния и перезаписи.
Принадлежащая приложению регистрация MCP `kitbash` считается устаревшей до переподключения:
оно заменяет её на `ruleblend` и мигрирует принадлежащий приложению встроенный скилл.
Чужой сервер или скилл с прежним именем сохраняется.

Форматы инструкций `kb` и `kb1` остаются читаемыми после Kitbash → Ruleblend.
Новые записи используют `rb1`; первая запись с изменением содержимого переводит старую
область в `rb1`, не меняя ручной текст снаружи.

| Путь | Содержимое | Можно восстановить автоматически |
|---|---|---|
| `library/blocks/<id>.md` | YAML frontmatter: name, description, version, type, необязательные `heading`/`headingLevel`, `variants`, `source`/`forkedFrom` субагентов; затем тело | нет |
| `library/groups/<id>.yaml` | Определение группы | нет |
| `library/profiles/<id>.yaml` | Переносимое определение профиля | нет |
| `library/skills/<id>/meta.yaml` | Метаданные скилла и происхождение из Git | нет |
| `library/skills/<id>/files/` | Полное переносимое дерево скилла с корневым `SKILL.md` | нет |
| `library/.git/` | JGit-репозиторий: каждое сохранение — локальный коммит; remote — необязательный участник двусторонней синхронизации | нет |
| `config.json` | Проекты, привязки профилей, области правил, настройки, окно, панели, переключатели агентов, места, сохранённые локальные правки, скрытые записи | нет |
| `backups/` | Ручные снимки целых файлов и manifest `index.json` | нет |
| `mcp-state.json` | Последняя запись Ruleblend в MCP-конфигурации агентов | При потере копии безопасно становятся чужими |
| `skill-state.json` | Отпечатки полных деревьев установленных скиллов | При потере копии безопасно становятся чужими |
| `subagent-state.json` | Отпечатки принятых отдельных определений субагентов | При потере копии безопасно становятся чужими |
| `sources-state.json` | Время проверки, remote HEAD и upstream-отпечатки импортированных скиллов/субагентов | да |
| `targets.index` | Кеш режимов целей и хешей блоков с контрольной суммой | да |
| `ruleblend.lock` | Межпроцессная advisory-блокировка библиотеки, config, целей и sidecar | да |
| `launchers/` | Сгенерированные macOS `.command` для запуска CLI агента в проекте | да |

<a id="line-endings"></a>
### Переводы строк

Локальная настройка LF/CRLF по умолчанию равна LF на всех платформах. Сгенерированные
блоки, группы, профили и метаданные скиллов используют её на диске; Git хранит определения
с LF, поэтому машины с разными настройками разделяют одни объекты и ревизии.
Управляемые области правил применяют настройку при следующей записи, сохраняя каждый байт
снаружи. Локальный редактор форматирует `SKILL.md`; импортированные payload, соседние
ресурсы, бинарные файлы и backups сохраняют исходные байты.
Библиотека владеет отмеченными секциями `.gitattributes` и `.git/info/attributes`;
вторая защищает payload даже от вложенных upstream-атрибутов. Локальные для репозитория
`core.autocrlf=false` и явный `core.eol` согласуют native Git и JGit, не меняя настройки машины.
При старте и смене настройки нормализуются только чистые определения; каноническая миграция
коммитится без повышения версий объектов и переписывания истории. Staged и несохранённые
правки сохраняются. Сторона слияния, изменившая только нормализацию, не вытесняет настоящую
правку с устройства, ещё использующего прежнюю политику.

Заголовок проекта запускает агентов, CLI которых обнаружен на машине. На macOS созданный
shell-скрипт передаётся терминалу через `open`: это даёт интерактивный терминал и работает
с любым приложением, открывающим `.command`, а не только со scriptable-терминалами.
Скрипт запускает агент через login shell пользователя: Finder передаёт минимальный PATH
из `launchd`, без Homebrew, nvm и mise, а агент повторно читает PATH при запуске `node`.
Проверка, обнаружившая executable, определяет и необходимость interactive shell;
запуск повторяет уже работавший способ. Доступные агенты определяются автоматически;
выбор терминала и строка аргументов по агентам хранятся в `config.json`.

Windows ищет native CLI через PATH/PATHEXT и стандартные каталоги установки пользователя.
Относительные PATH и текущий проект исключены, чтобы случайно не запустить executable
из проекта. Windows Terminal получает encoded PowerShell payload; при недоступном alias
открывается новая PowerShell-консоль. Явно можно выбрать Windows Terminal, PowerShell или cmd.
Payload создаёт .NET-процесс с явным рабочим каталогом: это сохраняет Unicode на Java 17
с ANSI code page и обходит разбор `;` терминалом в путях и аргументах.
Native executable используют CRT quoting; `.cmd`/`.bat` с `%*` — два слоя cmd escaping.
Переносы строк в batch-аргументах отклоняются до запуска: cmd не может безопасно их передать.
Windows launcher-файлы не сохраняются. Выбранные редакторы используют тот же способ запуска.

Состояние машины находится вне Git библиотеки: remote содержит только переносимое
содержимое и историю. `config.json` совместим в обе стороны через `ignoreUnknownKeys`
и `coerceInputValues`; новые поля получают значения по умолчанию при чтении старого файла.

Id объектов — переносимые одиночные имена файлов, проверяемые до построения пути чтения
или записи. Для блоков зарезервированы `ruleblend-import` и `kitbash-import`: миграция
redirect иначе приняла бы пользовательское правило за указатель. Генерация id из имени
тоже их пропускает. На всех ОС запрещены Windows device names, конечные точки/пробелы
и регистровые алиасы; библиотека macOS остаётся пригодной для Windows.
Деревья скиллов дополнительно запрещают коллизии файл/каталог. Архивные и Git-пакеты
проверяют все выбранные объекты относительно текущих имён до записи; свежие Git checkout
проверяют пути дерева до того, как Windows сможет схлопнуть два файла в один.

Идентичность проекта разрешает существующие filesystem-алиасы, включая junctions,
через ближайшего существующего предка и сворачивает регистр на Windows.
Несуществующие проекты сохраняют лексическую идентичность. Ключи config и sidecar
мигрируют при чтении и сохраняются при следующей записи; привязки и настройки объединяются.
При конфликте побеждает неактивная привязка; членство проекта сохраняет первый set.
До сохранения миграции исходный config атомарно записывается в
`config.json.before-path-migration`, с номером при занятом имени; конфликтные значения
и неизвестные поля остаются доступны для восстановления. Конфликтные ownership-записи
сохраняются, но не разрешают перезапись установленной копии. Ручные backups используют
ту же идентичность файла, сохраняя исходные адреса blob; миграция пути не теряет снимок,
для восстановления берётся последний совпадающий.

`config.json.projectProfiles` связывает нормализованный ключ проекта с упорядоченными
`{id, active}`. Это состояние машины: привязка относится к checkout, а не переносимому
профилю. Удаление проекта удаляет привязки вместе с проектом и состоянием места,
не оставляя режим от старого checkout.

<a id="profiles"></a>
## Профили

**Группа** — переносимый аддитивный набор для установки; установка и удаление затрагивают
только копии с origin этой группы. **Профиль** — переносимый версионируемый режим проекта:
привязывается только к проекту, включается/выключается там, а удаление согласует его участников.
Профиль включает плоские группы и прямые правила, MCP-блоки, скиллы и субагентов.
Группы и профили не включают другие профили: это единственный уровень вложенности.

Переносимое определение — `library/profiles/<id>.yaml`; упорядоченные привязки и `active` —
только `config.json.projectProfiles`, вне Git, экспорта и импорта библиотеки.
GUI предлагает **merge** (сохранить текущую установку как базу) или **replace**
(удалить базу после показа затрагиваемых объектов). MCP предоставляет оба режима
через `attach_profile`: Replace требует revision из `get_project_profiles`, проверяемую
под lock относительно привязок, базовых копий и определений библиотеки до удаления.
Общая политика удаления защищает изменённые копии и сообщает каждый отказ или ошибку.
`install(profile_id)` сохраняет Merge; `set_profile_active` переключает привязку без
отсоединения; `uninstall(profile_id)` выключает и отсоединяет её.
GUI-отсоединение сначала выключает привязку и выполняет согласование, оставляя ровно
то же, что выключение, затем удаляет саму привязку.

Удаление объекта библиотеки убирает его из всех профилей и групп: иначе согласование
продолжит искать отсутствующий id. Удаление профиля отсоединяет его от всех проектов:
машинная привязка имеет смысл только при существующем профиле.

Отдельного базового набора нет. База — все установленные объекты без `p=<profile>`,
включая `g=<group>`; она побеждает при совпадении с активным профилем.
Управляемые заголовки правил сохраняют origin в manifest (`:g=<id>` или `:p=<id>`;
прежний голый id означает группу); sidecar MCP, скиллов и субагентов хранит тот же origin.
Только запись с явно указанным origin задаёт его. Запись без origin — обновление,
восстановление, индивидуальная или массовая установка поверх копии — сохраняет её
прежнего владельца, не превращая участника в базу. Обновление сохраняет позицию правила.

`ReconcileProfiles(project)` приводит установку к базе плюс всем активным профилям,
передавая установку, удаление и смену origin существующим ownership-aware сервисам.
Общий объект нескольких активных профилей имеет одну физическую копию;
порядок привязок выбирает `p=`. Выключение профиля передаёт origin оставшемуся владельцу.
Защищённая ручная правка не перезаписывается и не удаляется, а остаётся и попадает в отчёт.

Копия удалённого объекта библиотеки тоже убирается: без библиотечного тела обычные
`InstallPolicy` и remove не могут принять решение, поэтому сервисы выполняют `removeOrphan`
по id. Правило сравнивается с manifest, скилл/субагент/MCP — с записанным fingerprint
или config. Совпадающая с записью копия удаляется, любая другая защищается как локальная
правка. Это относится лишь к profile-owned копиям; базовая копия удалённого объекта
остаётся до явного удаления пользователем.

Переключение профиля немедленно записывает файлы цели, но не гарантирует перечитывание
работающим ассистентом. Home и заголовок проекта перечисляют доступные включённые
адаптеры с `profileSwitchRequiresRestart`; пользователь перезапускает сессии.
Флаг принадлежит адаптеру, поэтому уведомление следует поведению агента, а не догадке UI.

`config.json.places` хранит навигацию: `pinned` и `recent` — id мест
(`agent:<id>` / `project:<absolute path>`), `sets` — именованные наборы ключей проектов.
Это состояние машины: набор checkout не экспортируется как группа объектов библиотеки.
`recent` хранит пять последних мест, новые первыми. Проект входит **не более чем в один set**:
дерево списка и агрегирование Coverage не должны неоднозначно определять место установки.
Удаление проекта в одной записи убирает его pin, recent и членство в set.

`config.json.keptDrifts` хранит ответ «оставить правку»: ключ места → id объекта →
SHA-256 оставленной копии. Решение переживает переходы между экранами и перезапуски;
оно локально для checkout. Digest скрывает только принятую правку: следующая правка
того же объекта снова показывается. Restore, сохранение новой версии и remove очищают запись.

`config.json.ignoredEntries` связывает место с ключами чужих физических записей,
которые пользователь скрыл. Каталог не меняется; discovery продолжает отмечать запись
как ignored, и новый каталог с тем же ключом остаётся скрыт до явного восстановления показа.

Аддитивный набор объектов — **группа**; режимы проекта задаются профилями.
Правила и MCP-серверы входят в `blockIds`, скиллы — в `skillIds`.
Группа версионируется и хранится в библиотеке, переносится с экспортом и Git-историей,
доступна в списках объектов. Настройка проекта становится одной установкой набора.
Сохранение места захватывает текущую установку в группу, не включая группы в самих себя:
членство остаётся плоским списком читаемых агентом объектов. Существующее **имя** обновляет
группу, не создавая дубль; `LibraryRepository.saveGroup` повышает версию лишь при смене
участников. Второй локальный набор был отвергнут: две сущности для именованного набора
объектов заставляли выбирать между ними, хотя лишь одна была переносимой,
версионируемой и видимой в библиотеке.

Необязательный внешний Git — двусторонняя синхронизация, а не backup.
Локальные коммиты остаются авторитетными до начала sync. Каждый sync сначала fetch,
затем fast-forward/merge, затем push итогового `HEAD`; force-push и push без fetch запрещены.
Отказ non-fast-forward или временный remote ref lock вызывает один повтор fetch/merge/push.
Fast-forward и слияние разных объектов проходят без уведомления.
При одновременном изменении блока, обычной группы или профиля сохраняются оба Git-родителя,
а локальное определение получает следующую числовую версию выше обеих.
Это *last-sync-wins*: текущее определение даёт устройство, синхронизирующееся последним;
обе версии остаются в истории. Delete-versus-modify восстанавливает сохранившуюся правку.
Слияние разрешается по объектам, не файлам: скилл — каталог, и пофайловое слияние могло бы
оставить дерево без `meta.yaml`. Восстанавливается всё победившее дерево, байты и executable bits.
Отчёт называет объекты библиотеки; Home показывает каждый разрешённый объект со ссылками
на историю и Compare, чтобы замена работы не была незаметной.
Эквивалентное нормализованное содержимое не конфликтует. Служебная `all` пересчитывается
по объединённым объектам в порядке записи библиотеки, а не text-merge: два порядка
иначе бесконечно повышали бы версии `all` и переустанавливали неизменённые группы.

Неразрешимое слияние откатывается, не остаётся незавершённым: pending merge запрещает
Git-сохранения и sync, делая библиотеку недоступной для записи до ручного вмешательства.
Пустая библиотека клонирует существующую настроенную ветку вместо несвязанного первого коммита.
Две непустые истории без общего коммита требуют решения в Settings: импортировать remote
через ту же политику слияния или сначала экспортировать локальную библиотеку в ZIP,
а затем атомарно заменить её удалённой веткой. Ошибка сети/авторизации сохраняет локальный коммит.
Library сохраняет и коммитит вне UI-потока, показывая заблокированное состояние прогресса.
Ручная синхронизация использует coroutine scope приложения: закрытие формы и навигация
не отменяют операцию и её результат.

Автоматический sync работает в daemon-потоке `LibraryGit`; fetch/push вне lock библиотеки,
поэтому сохранение завершается после локального коммита, а медленный remote не блокирует
вызывающий код и следующую запись. Ожидание UI ограничено: по таймауту sync продолжает
работать и не превращает завершённое локальное сохранение в ошибку приложения.
Разрешение входящих изменений в index/working tree берёт lock, только если есть что сливать:
иначе параллельное сохранение могло бы закоммитить промежуточный index под своим сообщением.
Целые sync тоже сериализованы: Home, Settings и worker могут запустить их одновременно.
Запрос sync происходит при старте, после каждого локального коммита и при возврате фокуса
не чаще раза в пять минут. Каждый push всё равно предваряется fetch/merge.
В очереди не более одного sync: он заберёт все коммиты, сделанные до его старта.
`lastRemoteSync` сохраняет ahead/behind, факт merge, разрешённые объекты, включая
восстановленные удаления, и ошибку для следующего UI-обновления.
URL, ветка и переключатель autosync — в `config.json`; HTTPS-секреты — в стандартном
Git credential helper пользователя, с fallback на `.netrc`.

Credential helper может открыть системный вход; запрос даёт пользователю две минуты.
Успешная операция approve-ит возвращённое описание credentials; повтор HTTP-авторизации
сначала reject-ит его. Секреты передаются UTF-8 pipes, не записываются в config и логи Ruleblend.
Windows дополнительно ищет стандартные установки Git for Windows, если desktop PATH
не содержит `git.exe`. Credentials используют тот же Unicode-safe запуск, что ассистенты.

`BackupService` хранит один слот на абсолютный путь (`<sha1>.txt`), записывает и
восстанавливает через `AtomicWrite`. Restore — точный откат, включая установки после снимка.

<a id="git-repository-imports"></a>
## Импорт Git-репозиториев

Library принимает HTTPS или локальный Git-репозиторий и shallow-клонирует текущую
default branch во временный каталог. Discovery сначала использует
`.codex-plugin/plugin.json`, затем `.claude-plugin/plugin.json`, иначе обычный `skills/`.
Объявленный Codex-путь `skills` разрешается только внутри checkout.
Каждый прямой дочерний каталог с `SKILL.md` предлагается отдельным скиллом;
репозиторий может объявить один скилл и в корне skills.

В том же checkout обнаруживаются субагенты по plugin-путям `agents`, native-каталогам
ассистентов и коллекциям `agents/`, `subagents/`, `categories/`.
Markdown требует agent frontmatter; документация исключается. Объявленный или native-путь
задаёт ассистента; общий Markdown сохраняет трактовки Claude Code и Kimi Code до явного выбора.
Codex принимает строковые TOML-поля, включая многострочные инструкции и `[instructions].text`.
Неподдерживаемое значение даёт ошибку отдельного файла с исходным текстом, а не неполное
определение. Discovery не пишет в библиотеку. До checkout Git-объекты ограничиваются:
20 000 файлов, 16 компонентов пути, 10 MiB на файл, 100 MiB всего; links и submodules запрещены.
Manifests и отдельные определения субагентов ограничены 1 MiB. Код репозитория не исполняется.

Отображаемая версия скилла берётся из plugin/package version; без неё — первые 12 символов
SHA коммита. Полный SHA сохраняется всегда, различая одинаковые версии разных ревизий.
Список источников выводится из `repository`, `revision` и относительного `path`
импортированных скиллов/субагентов: отдельного реестра источников, способного рассинхронизироваться,
нет.

Происхождение субагента дополнительно задаёт исходного ассистента. Выбирается ровно один
native-вариант, его поля не становятся defaults остальных ассистентов.
Числовая версия определения независима от SHA: посторонний upstream-коммит обновляет
происхождение без объявления изменения определения. Повторный импорт/обновление сопоставляет
репозиторий, путь и ассистента, сохраняя локальные id и членство.
Обычная запись не редактирует импорт и не удаляет source; редактируемая копия переносит
source в `forkedFrom` и начинается с v1. Оба поля передаются в block frontmatter через ZIP;
старые определения без них остаются локальными и редактируемыми.

Проверка источников двухуровневая. Один `ls-remote` читает HEAD каждого уникального
репозитория. Если HEAD совпадает со всеми импортированными из него ревизиями,
клонирование не нужно. Иначе один ограниченный shallow clone обслуживает все его пути;
fingerprint полного upstream-дерева сравнивается с библиотекой, отличая обновление
от коммита в другой части репозитория. У субагентов сравниваются разобранные переносимые
инструкции и native-поля, без локальных id и происхождения.
Отсутствующий путь и недоступный репозиторий — разные результаты; испорченный файл
субагента недоступен отдельно от остальных.

`~/.ruleblend/sources-state.json` хранит время последней проверки и remote HEAD по репозиторию,
upstream-fingerprint по пути скилла (для субагента — ассистент плюс путь), а также пути,
для которых репозиторий был доступен, но файл не найден. Так удалённый путь воспроизводится
из кеша, не отбрасывая весь результат. Это удаляемый UI-кеш, не provenance:
отсутствующий/нечитаемый sidecar начинается пустым; источники определяют текущие импорты.
По умолчанию проверки ручные; необязательный on-launch запускает такую же проверку один раз.

Обновление выбранных скиллов и субагентов разрешает все id и upstream-пути до записи,
группирует выбор по репозиторию и загружает каждый один раз. Полное совпавшее дерево
атомарно заменяет импорт, сохраняя локальный id и ссылки групп/установленных копий.
Удалённые upstream-файлы исчезают как часть замены.

Содержимое репозитория недоверенное: credentials в URL, удалённые схемы кроме HTTPS,
выход из checkout, symlinks, слишком большие файлы и деревья запрещены.
Сохранённое происхождение тоже недоверенное: архив мог принести любой URL, поэтому remote
повторно проверяется до check/update. Скилл может занимать корень репозитория;
служебный `.git` checkout никогда не захватывается. Свежий clone меняет index/reflog,
и их установка вызывала бы бесконечные ложные обновления.
Импорты доступны в редакторе только для чтения. *Create changed copy* копирует все
соседние файлы, сохраняет ревизию как переносимый
`forkedFrom { repository, path, revision }` при экспорте/импорте и выбирает свободные
id/имя с `-changed`: upstream-update не затрёт локальную правку.
Когда импорт с теми же repository/path переходит на новую ревизию, fork сообщает
об изменении upstream и открывает Compare с этим импортом. Отдельное upstream-дерево
и автоматическое слияние для fork не хранятся.

<a id="skill-installation"></a>
## Установка скиллов

Скиллы устанавливаются полными деревьями там, где у агента известен путь скиллов.
Claude Code: глобально `~/.claude/skills/<id>`, в проекте `<project>/.claude/skills/<id>`.
Codex использует только native `.codex/skills`.
Kimi Code и ZCode записывают native-корни `.kimi-code/skills`, `.zcode/skills`
и общий `.agents/skills` в обеих областях; Pi читает лишь общий корень.
Ruleblend оставляет `.agents/skills` отдельной shared-интеграции, не дублируя туда каждый
Codex-скилл. Проект записывает все деревья включённых агентов, пропуская агентов без пути скиллов.

`skill-state.json` хранит последний записанный fingerprint по цели, агенту и скиллу.
Точная библиотечная копия — `synced`; неизменённая установленная копия после изменения
библиотеки — `update-available`; неизвестная или изменённая вручную — `modified`.
Неизвестное/изменённое дерево требует явной перезаписи и никогда не удаляется обычным remove.
Только запись sidecar делает дерево управляемым: без неё даже совпавшая с библиотекой
копия остаётся чужой. Потеря state не создаёт владение по совпадению байтов.

Один физический путь могут разделять несколько агентов: Pi и shared-корни Kimi Code/ZCode
используют `.agents/skills`. Владение следует объявленным путям, а не id агентов:
запись удерживает дерево, если корень её агента с этим directory id в той же области
разрешается в тот же нормализованный путь. Удаление установки одного агента удаляет
его запись и native-копию; общее дерево остаётся до удаления последнего владельца,
даже если тот сейчас не входит в список агентов цели.

Executable intent — часть переносимого снимка. В библиотеке авторитетен `meta.yaml`;
`skill-state.json` хранит последние установленные executable-пути, включая orphan recovery.
Fingerprint покрывает пути, точные байты и executable intent. На POSIX используются
реальные mode bits, поэтому chmod — защищённая правка. Без POSIX-атрибутов берётся запись
установки, а не Windows ACL execution access. Старую запись без modes можно сопоставить
с текущей библиотекой; непроверяемое прежнее дерево остаётся защищённым.
Чужая локальная копия без POSIX modes захватывается как non-executable, без догадок по ACL/расширению.
Git import и source check читают modes из checkout index, обнаруживая и symlinks,
материализованные обычными файлами на Windows. Свежие skill clone отключают преобразование
переводов строк до checkout; Git библиотеки следует [общей политике](#line-endings).
ZIP и Git переносят одинаковые метаданные; POSIX-установка восстанавливает их.

При обновлении каталог скилла не исчезает (`DirectoryReplace`). Новое дерево готовится
в соседнем каталоге, старое копируется для отката, затем меняется на месте: каждый файл
попадает атомарным rename, `SKILL.md` последним, удаление лишних файлов — в конце.
Сканирующий ассистент всегда видит скилл; создание каталога другим инструментом не ломает запись.
Читатель может кратко видеть смесь старых/новых файлов, но при новом `SKILL.md` все новые
файлы уже рядом. Сбой на любом шаге или у следующего агента откатывает копию тем же способом.
Новый каталог публикуется одним rename; symlink или файл на месте цели отодвигается целиком,
ссылка не обходится. Библиотечное `skills/<id>` записывается так же.
Обмен целыми каталогами через `renamex_np(RENAME_SWAP)` / `renameat2(RENAME_EXCHANGE)`
отвергнут: для JDK 17 нужна новая native-зависимость JNA либо JDK 22+ с FFM;
файловые системы без такого вызова всё равно требуют двух rename с промежутком отсутствия.

<a id="integration-mechanics"></a>
## Механика интеграции

**Файл цели — единственный источник истины для управляемых областей правил.**
Состояние переносится с файлом: новый clone, машина или участник читают то же, что Ruleblend.
Отдельной install database и manifest рядом с файлом нет: второй источник разошёлся бы с первым.
`~/.ruleblend/targets.index` — удаляемый кеш.

Владение определяется для каждого файла по его содержимому:

| Режим | Признак | Значение |
|---|---|---|
| `none` | — | Не управляется |
| `partial` | notice + header + terminator | Одна управляемая область рядом с ручным текстом |
| `owned` | Только header | Весь файл строится из библиотеки |
| `legacy` | `N+1` строк маркеров | Старый поблочный `kb`: читается, больше не записывается |

Весь manifest области `rb1` помещается в начальную строку:

```markdown
<!-- Ruleblend-managed. Do not edit below; changes are overwritten. -->
<!-- rb1 8f2a1c04 git-commit-no-push@2:412 swift-style@1:180:g=ios-projects -->
...rendered blocks, back to back...
<!-- rb:end -->
```

- `rb1` — маркер и версия формата.
- `8f2a1c04` — хеш отрисованного тела; несовпадение означает ручную правку.
- `<id>@<version>:<utf8-byte-length>[:<origin>]` — блоки в порядке документа.
  Origin — `g=<group-id>` или `p=<profile-id>`; старый голый id означает группу.
  Длина в байтах отделяет склеенные тела без второго manifest.
  `owned` включает notice в ту же первую строку: `<!-- rb1 owned … -->`.

Два Kitbash-формата остаются читаемыми: поблочный
`<!-- kb <id> v<version> [g:<group>] [<hash>] -->` плюс `<!-- kb:end -->` на область;
поздний wrapped-формат `<!-- kb1 … -->` с тем же `<!-- kb:end -->`.
Первая запись с изменением содержимого переводит оба в `rb1` / `rb:end`.
Старые owned-notices читаются и заменяются Ruleblend-notice при этой записи.

- **Доступ через `TargetEncoding`** (`LegacyMarkers` / `WrappedRun` / `FullFile`):
  `IntegrationService` выбирает реализацию по файлу и дальше не зависит от encoding.
- **Состояние блока:** `synced` — хеш/версия совпадают с библиотекой;
  `update available` — библиотека новее; `modified` — копия отличается при той же версии
  или не сходится хеш. Цель с несколькими файлами сообщает худшее состояние,
  чтобы ручная правка не скрылась за другими файлами.
- **Без незаметной перезаписи.** Изменённое правило восстанавливается из библиотеки
  или сохраняется туда следующей версией. То же относится к MCP-entry: целый server object
  соответствует одному библиотечному блоку. У скилла нет единого тела; доступны restore/keep.
  Restore перестраивает управляемую область по текущей библиотеке.
  Save сначала выделяет выбранное тело по manifest и неизменённым соседям;
  если поменялось ещё одно правило области, операция отклоняется как неоднозначная.
  После library commit цель проверяется снова и атомарно переписывается с новым marker version.
- **Редактирование из Projects.** Строка управляемого правила открывает тот же Library editor.
  Успешное сохранение записывает новую версию обратно в исходное место, сохраняя base/group/profile
  origin. Если копия изменилась, пока редактор был открыт, запись в цель отклоняется,
  а новая версия библиотеки сохраняется.
- **Reorder меняет только порядок.** `TargetEncoding.reorder` использует тела из файла,
  не переписывая их и не перемещая внешнее содержимое. Неуказанные id сохраняют взаимный
  порядок после указанных. Область, не совпадающая с manifest, отклоняется:
  границам изменённых блоков нельзя доверять. Legacy-перестановка остаётся в своей
  непрерывной области и не пересекает ручной текст между областями. `rb1` имеет одну
  область, поэтому любой блок может попасть на её край. Неизменившийся порядок ничего
  не записывает и не запускает legacy → `rb1` миграцию.
- **Заголовок блока.** Необязательные `heading`/`headingLevel` во frontmatter дают
  первую строку области, пустую строку и тело через `regionFor`. Заголовок входит в хеш и длины manifest.
  Отдельное хранение позволяет одним действием менять имя и задавать глубину по блокам;
  пустой заголовок намеренно сливается с окружением, как все прежние блоки.
  При принятии локальной правки ведущий heading отделяется обратно, чтобы не попасть
  в тело и не продублироваться при следующей установке.
- **Установка группы** разворачивается в отдельные области с `g=`. Участники обновляются
  независимо; удаление группы удаляет их, кроме отдельно установленных копий.
- **Внешнее содержимое никогда не меняется**, кроме пользовательского *Save to library*
  с включённым replace. Длины и хеши manifest используют LF-нормализованные тела;
  offsets переводятся обратно в исходный текст. Partial-область владеет маркерами
  и одним переводом строки terminator, но не следующими пустыми строками.
  Удаление/legacy migration сохраняют внешние байты, смешанные переводы строк и пробелы;
  disown сохраняет и исходные байты тела. Новое управляемое содержимое использует
  выбранный LF/CRLF. Нормализованный preview служит лишь отображению, не записи.
- **Disown** убирает header/terminator, оставляя содержимое точно как на диске.
  Wrapped-файл также можно вернуть к legacy-маркерам через core API.
- Запись пользовательских файлов атомарна: temp + rename.

<a id="adopting-existing-rules"></a>
## Принятие существующих правил

Ручные правила обычно существуют до Ruleblend. Файлы с содержимым вне управляемых
областей показываются в **Found in project** (**Found in agent** для глобальной цели)
палитры Place: путь относительно корня и число неуправляемых строк.
Принятие проекта начинается здесь; это единственная поверхность с таким действием.

- Сканируются `Target.ownedFiles()` и, под **Referenced via @import**, транзитивные
  Claude Code `@path`. Импорты разрешаются от корня цели, как у Claude Code;
  сканируется только ручной текст, сломанные пути пропускаются и отмечаются `⚠` в диалоге.
- **Save to library** открывает имя, описание и *Replace the original text with a managed region*
  (по умолчанию выключено). Выключено — копирование без изменения файла.
  Включено — текст вырезается и заменяется областью на месте первого фрагмента
  одной атомарной записью; результат `synced` и функционально прежний для агента.
  Library commit выполняется первым: текст попадает в Git до удаления из цели.
  Новое правило из проекта получает область этого проекта; из globals — глобальную.
  Перезапись совпавшего блока сохраняет его область.
- **Несколько секций.** При ≥ 2 подходящих Markdown-секциях диалог показывает checklist.
  Разделение по самому верхнему уровню заголовков, с проходом внутрь одиночной оболочки,
  не смешивает родительский текст с чужим. Извлечение без потерь: секции только с heading
  или comment сохраняются для write-back, но не предлагаются.
  `slugify` эффективного имени и Jaccard similarity сопоставляют секции с библиотекой:
  **new**, **duplicate**, **similar**, с выбором Skip / Overwrite / Create new по каждой.
  Heading сохраняется отдельно у блока и воспроизводится при записи.
  С replace выбранные секции и существующая область должны образовать непрерывный отрезок;
  область занимает его место, сохраняя единственную область и расположение строк.
  Сохранённая секция внутри отрезка потребовала бы перемещения, поэтому выбор отклоняется
  до сохранения с указанием препятствующей секции. Writer повторно отклоняет такой план
  и план, чей текст уже не совпадает с файлом.
- **Split** (`Splitter` в `core`) делит правило по произвольным границам из Library editor
  или строки adopt-диалога. В Library исходный блок не меняется, части получают его группы.
- **Edit file** открывает найденный файл для ручного исправления. Чистый `@AGENTS.md`
  показывается как уже настроенный pointer, не предлагается к принятию.
  Снимки целого файла (`backups/`) и смена владения доступны в заголовке текстового файла Place
  (см. [UI](#ui)).

<a id="subagent-formats"></a>
### Форматы субагентов

`AgentAdapter` объявляет формат и глобальные/проектные каталоги субагентов независимо
от правил и скиллов. Определение всегда `<id>.<extension>` и отрисовывается до проверки
ownership/state: installer отпечатывает ровно записанные байты.
Claude Code использует `~/.claude/agents/<id>.md`, `<project>/.claude/agents/<id>.md`;
Kimi Code — аналогичные `~/.kimi-code/agents/`, `<project>/.kimi-code/agents/`;
Codex — только `~/.codex/agents/<id>.toml`, с escaped-телом в `developer_instructions`.

`name`, `description` и тело инструкций переносимы, хранятся у `Block`.
Модель, список tools, цвет одного ассистента не обязаны иметь смысл для другого;
они хранятся в `Block.variants` по id агента. `SubagentFormat` объявляет понимаемые поля
через `SubagentFieldSpec`: канонический `id`, собственный `nativeKey`
(`model` у Claude Code/Codex, `modelPreference` у Kimi Code), вид редактирования
и необязательные подсказки значений. Канонический id сохраняет узнаваемость настройки,
native key — требуемый синтаксис файла.

- **Ничего не выдумывается.** Ассистент без variant получает только переносимое определение,
  без переноса модели другого ассистента.
- **Ничего не теряется.** Parser сохраняет неизвестное формату поле под native key:
  принятие чужого определения и переустановка не удаляют неизвестные настройки.
  Вложенная map остаётся в файле, не уплощается; список scalar превращается
  в принимаемую этими агентами строку с запятыми.
- **Variant не переходит к соседям.** Render читает только variant записываемого агента.

У изученного ZCode нет стабильного standalone-формата определений:
`~/.zcode/cli/agents/` — хранилище сессий, а plugins задают собственных агентов.
Адаптер возвращает `UNSUPPORTED`, не записывая Markdown в runtime-каталог.
Матрица получает `NOT_SUPPORTED`, как Pi без функции субагентов.
Причина хранится в документации, не отдельным модельным значением, которое не создаёт ни один адаптер.

<a id="subagent-ownership-and-drift"></a>
### Владение субагентами и локальные изменения

Standalone-определения не содержат Ruleblend-маркеров. `subagent-state.json` хранит
SHA-256 по ключу цели, id агента и субагента: точные UTF-8 байты `SubagentFormat.render`,
а не переносимый блок и не повторно разобранный файл. Запись соответствует Markdown
Claude Code/Kimi Code и TOML Codex.

Неизвестный файл с отличающимися от render байтами — конфликт без перезаписи до явного выбора.
Adopt записывает текущие байты обычного файла, не меняя его. В этот момент файл разбирается
и сравнивается с разобранным render: если поля/тело равны, а отличаются лишь layout,
порядок полей, quoting или пустая строка, сохраняется `equivalentRender` — fingerprint
эквивалентного render. Пока оба fingerprint совпадают, файл `SYNCED`;
изменение render библиотеки даёт update, как и принятое изначально отличавшееся определение.
Любое последующее изменение байтов — `MODIFIED`. Проверки состояния сравнивают байты.
Без записи даже совпадающий файл чужой: владение задаёт sidecar, не случайное совпадение.
ZCode/Pi в этом процессе не имеют ни пути, ни записи.

<a id="subagent-library-ui"></a>
### Субагенты в Library

Каталог индексирует субагент отдельно от правил, MCP, скиллов и групп, сохраняя
переносимый `Block` и членство в `blockIds`. Редактор показывает секции поддерживающих
субагентов ассистентов из field specs плюс принесённые чужим определением поля.
Все поля — свободный текст: модели/tools меняются независимо от релизов Ruleblend.
Сохранение чужого определения помещает поля только в variant исходного ассистента.

Библиотека до появления variants содержит общий `model`. `BlockFile` при чтении переносит
его трём ассистентам, которым он мог относиться тогда, и перестаёт писать старый ключ.
Список миграции фиксирован: новый ассистент не наследует значение, выбранное до его появления.
Library bulk, Place, usage, history и Coverage используют `InstallItem.Subagent`
и тот же `SubagentInstallService`, что status scan. Он единственный writer:
UI сам не render-ит, fingerprint-ит, принимает или удаляет native-определения.
Неподдерживаемый агент не даёт destination; ZCode/Pi видны как неподдерживаемые,
а не получают угаданный формат.

Разобранное чужое определение становится Library `SUBAGENT` и принимается без перезаписи.
Sidecar хранит принятый fingerprint и физическое имя, если занятый Library id отличается
от исходного filename; discovery разрешает запись по этому адресу.

<a id="place-entry-discovery"></a>
### Обнаружение записей Place

Skills, Subagents и MCP показывают физические записи цели, а не только объекты Library.
Discovery читает лишь поддержанные installer-ами пути: прямые дочерние каталоги с
`SKILL.md`, standalone-определения в точных каталогах/формате адаптера, MCP-записи
`mcpServers` JSON или Codex `[mcp_servers.*]`. Dotted sub-table принадлежит серверу,
под которым записана, а не образует отдельный сервер.
Обход проекта и чтение других секций конфигурации не выполняются; проектные секции
глобального Claude config не считаются проектными записями. Сервисы возвращают текст
и физический адрес: render UI не читает пользовательские файлы.

У адреса один origin. Запись sidecar с существующим Library-объектом — `MANAGED`;
с удалённым — `ORPHAN`; без sidecar — `FOREIGN`; скрытый чужой адрес из
`config.json.ignoredEntries` — `IGNORED`. Ключ — физический адрес, не имя root/id Library:
разные агенты могут иметь одноимённые корни. Discovery/классификация только читают.
Чужие/ignored записи не влияют на status dot: он описывает только управление Ruleblend.

Поддержанные чужие записи можно сохранить в Library и принять записью текущего состояния,
не переписывая source. Сохранение и запись ownership — один шаг: иначе созданный объект
оказался бы чужим на собственном адресе. Чужая запись с именем существующего Library-объекта
принимается под ним, без предложения создать ещё один дубликат.
При отличающемся содержимом показывается update или modification.
Release скилла/субагента/MCP удаляет только ownership-записи; физическая копия остаётся чужой.
Чужой адрес показывается один раз даже при одноимённом Library-объекте.
Orphan может восстановить записанный Library-объект или удалить лишь sidecar.
Hide не меняет файл/sidecar. Вне управляемых областей содержимое пользователя не меняется;
исключения — явный *Save to library* с replace либо подтверждённое удаление конкретного
чужого каталога скилла/MCP-entry. Удаление MCP сохраняет соседние записи config.

Глобальные правила доступны всем целям. Правило проекта — только точно тому же
нормализованному пути. Смена области не удаляет уже установленную область у другой цели:
она остаётся видимой там до удаления пользователем.

**Один управляемый файл правил на проект.** Общий файл — `AGENTS.md`.
Claude Code читает `CLAUDE.md` с обычным pointer `@AGENTS.md`, без маркеров:
marker-пара утроила бы защищаемую одну строку, поэтому import записывается без владения им.
Pointer добавляется, когда в `AGENTS.md` есть управляемая область и import отсутствует.
Удаляется только если pointer состоит ровно из этой строки, а цель больше не содержит
ни области, ни ручного текста. Pointer рядом с другим текстом или на ещё непустую цель
сохраняется: снаружи области нельзя отличить свою строку от пользовательской.
`Target.files()` — файлы правил; `redirects()` — пары pointer → target;
`ownedFiles()` — оба вида. Идемпотентный `IntegrationService.syncRedirects`
переносит старые правила из `CLAUDE.md` в `AGENTS.md`, а import-region под служебным
`ruleblend-import` / прежним `kitbash-import` превращает в обычную строку.
Оба id остаются зарезервированными: если прочесть такой region как правило, миграция
перенесёт его в файл назначения, создав import файла в себя.

**Detection** использует config-каталог, не файл инструкций: у установленного,
но ещё не настроенного агента `AGENTS.md` может отсутствовать.
Каждая загрузка Integration обнаруживает агентов заново, поэтому новые появляются сами.
Агенты с одним project filename разделяют файл: единица записи — файл, не агент.

<a id="ui"></a>
## UI

Compose Desktop использует общую сворачиваемую навигацию, верхнюю панель 44 dp
и типизированные routes. Sidebar анимируется между 204 и 68 dp без замены layout:
иконки остаются в одной колонке, подписи исчезают до обрезания, свёрнутые пункты —
квадратные targets с hover-подписями. Когда toggle не помещается, раскрывает brand tile.
Состояние хранится в `config.json.sidebarExpanded`. Settings закреплён внизу отдельно
от Home, Place (Targets / «Проекты»), Library и Coverage. Resolve — вложенный flow
из Home/Coverage. Экраны используют следующие routes:

- **Home:** attention feed агрегирует один cross-place scan, не поток alerts.
  Карточка на класс проблем: ручные изменения блоков, доступные обновления,
  непринятый ручной текст, legacy-разметка, установленный неуправляемый агент.
  В ней total, места и исходные файлы. Подсчёт один раз на scan, не при recomposition:
  scan читает файлы всех мест. Повторное сканирование явно; сбой сохраняет прежний
  снимок, не обнуляя всё из-за одного нечитаемого места. Нетронутый ненастроенный
  проект не считается проблемой. «Нечего делать» после scan отличается от «ещё не сканировали».
  Render только рисует snapshot, не читает файлы/не пересчитывает счётчики.
  Карточка несёт одно действие и раскрываемые ссылки на места; конфликт ведёт в Resolve.
  Единственная запись Home — скрыть неуправляемого агента, убрав его из fleet,
  а не временно закрыть возвращающуюся карточку.
  Различаются три empty states: не сканировали — scan; пустая библиотека — Library;
  синхронный fleet — coverage. Под feed здоровье fleet повторяет группировку places:
  agent globals, именованные sets, проекты без set. Chip места делит установленные
  объекты по трём состояниям; затем те же pinned/recent shortcuts.
- **Library:** facets (тип, группа, область, usage, Git source) → список → inspector;
  редактирование — отдельный полноэкранный focus view. Inspector показывает тело/участников,
  Git provenance импорта скилла/субагента, места установки с состоянием и ссылкой в Place,
  историю объекта из коммитов библиотеки.
  Правила редактируются как Markdown и меняют область; MCP остаются глобальными
  и имеют structured form. Git-импорты неизменяемы в редакторе/Compare, доступны update/fork.
  Общий Git import dialog требует выбора ассистента при неоднозначном определении;
  уже импортированные не отмечены, чтобы повторное обнаружение не заменяло их молча.
  Home/Settings группируют оба вида по repository, сохраняя отдельные пространства id.
  Группы редактируются inline в focus view и включают правила, субагенты, MCP, скиллы.
  Checkbox строк выбирает массовую установку в места, добавление в группу, экспорт.
  Массовые update/remove принадлежат Coverage с видимыми объект × место парами;
  второй вход из Library не создаётся.
  Перевод тела правила/скилла открывается рядом по запросу
  (см. [перевод](#translation)), не автоматически на каждый символ:
  правило пишут один раз и читают многократно, drafts не должны занимать переводчик.
- **Place:** список мест → содержимое одного места по вкладкам Rules, MCP, Skills, Subagents,
  с теми же названиями, что в Library. Вкладка отвечает «что здесь есть»;
  filename — адрес уровнем ниже, заголовком секции. Все адреса вида читаются одним scroll,
  включая `AGENTS.md`, pointer и несколько MCP-config, без отдельного клика на файл.
  Вкладка показывает худшее состояние и число объектов, включая ноль.
  Ownership принадлежит секции файла; pointer показывает import, не список блоков.
  Пустой файл назван в заключительной строке «Nothing in: …», а полностью пустой вид
  показывает одно сообщение и будущие адреса записи, не экран пустых секций.
  Rules, Skills, Subagents, MCP имеют отдельные default fold states в `config.json`;
  outlined `+`/`−` заголовка раскрывают/сворачивают все записи текущей вкладки на этот визит.
  Rules/MCP сохраняют file-level Edit; скиллы/субагенты редактируются на строке определения,
  не в заголовке каталога.
  Единица preview, как записи, — файл: ручной текст показывается на своём месте,
  managed regions выделены и перечисляют блоки с версией, группой и состоянием.
  Порядок исходный, область не обязательно последняя. Изменённая область перечисляет
  заявленные manifest блоки и раскрывает нынешнее тело: один блок владеет всем телом,
  в нескольких неизменённые библиотечные соседи выделяют изменённого, как `localChange`.
  Тело пусто только при невозможной атрибуции: нет блока в Library, изменились два,
  либо разделение неоднозначно.
  MCP раскрывает локальный config против библиотечного в одной сериализации.
  Если копии по агентам различаются, показывается каждая и её собственное save as version:
  какое тело станет единым библиотечным — решает пользователь; сохранение записывает
  его и другим агентам места.
  Перевод — на секцию файла, только для prose, без второго столбца config/skill directory.
  Заголовок текстового файла позволяет snapshot/restore всего файла, legacy migration,
  переключение warning notice, disown. Restore/disown подтверждаются; все пять действий
  делегируют atomic core, не создавая второй ownership-путь для config/skills.
  Заголовок проекта перечисляет всех обнаруженных видимых ассистентов, включая выключенных
  здесь; переключение меняет только `config.json.disabledAgents`, не файлы на диске.
  Справа library palette: сначала найденные ручные файлы с adopt/editor,
  затем рекомендации set, затем каталог по типу и поиск. Используются тот же Library catalog
  и текущие статусы места, не второй index. Группа берёт худшее состояние участников.
  Рекомендации доступны лишь проекту в set: «installed in 6 of 8» считает siblings
  относительно всего set, globals не имеют peers.
  Save place as group захватывает нынешнюю установку без строк групп.
  Scroll position хранится по месту; вход возвращает к его секции.
  Слева фильтр places, pinned/recent, затем канонические globals/sets/проекты без set.
  Pinned/recent намеренно повторяют канонические места, recent исключает pinned.
  Визит — только явный выбор; fallback selection не пополняет recent.
  Fold секций — состояние сессии, не настройка.
- **Coverage:** одна матрица «что где установлено» из общего scan и Library catalog,
  без собственного index. Строки: объекты, виды, группы; столбцы: globals как группа,
  sets и проекты без set. Столбец агрегирует *набор мест*, не рисует сразу сетку 304 × 30.
  Ячейка считает объекты, не writes: `installed / members`, bar по трём состояниям,
  состояние объекта — худшее по местам столбца.
  Неприменимые объекты исключены из знаменателя: правило другого проекта, скилл без
  читающего каталога. Если не подходит ничего — dash.
  Scan в памяти; фильтры типа, only installed, needs attention и fold столбцов
  агрегируют без диска. Lazy-строки делят горизонтальный scroll с header.
  Виды/группы раскрываются в объекты; all objects остаётся summary без дубля видов.
  Все строки/столбцы можно свернуть вместе. Globals изначально открыты при ≤ 4 местах,
  независимо от default fold строк; раскрытие — session state.
  Summary, filters и column controls раздельны, чтобы status не путать с toggle.
  Конфликт ведёт в Resolve; update включает attention filter, не массовую запись.
  Visibility ассистентов — menu без сдвига матрицы, legend внизу.
  Непрерывная группа столбцов имеет один band/fold control без повторения parent
  на каждом child. Place name отделён от group name и при одном месте:
  нижний header открывает destination, band сворачивает группу.
  Drill-down перекраивает тот же scan: раскрытый объект считает *места*;
  dash следует тому же правилу, что aggregate, и не противоречит summary.
  Запись возможна только в ячейке один объект × одно место: aggregate не угадывает
  пользователя и не запускает незаметную массовую правку.
  Shared installer защищает локальную правку/чужую область как Library bulk,
  затем перечитывает fleet, не патчит matrix.
  Visibility пишет тот же `hiddenAgents`, что Home; скрытые доступны для восстановления
  здесь/в Settings, хотя перестают быть places.
  Для bulk отмечаются любые строки кроме all objects, раскрытые и закрытые:
  batch должен быть явно выбранным/суженным набором.
  Сначала строится plan: выбранные объекты × столбец превращаются в точные пары,
  исключая уже достигнутое состояние и отказы scope с показанными счётчиками.
  Install/remove выбирают целевой столбец; update берёт устаревшие копии scan,
  не изменённые вручную, без нового выбора места.
  Применение по одному месту через shared installer; отказ места не отменяет остальные.
  Report называет записанное, пропущенное и отказавшие места.
- **Resolve:** конфликты общего cross-place scan, без собственного index.
  Вход — core `MODIFIED`; классификация та же, что выдача localChange:
  attributable hand edit против неоднозначной области с несколькими изменёнными блоками.
  Изолированная правка доказывает неизменность соседей, поэтому attributable/ambiguous
  не смешиваются в одном файле. Если изоляция невозможна, все кандидаты области ambiguous:
  сломанные offsets делают соседей нечитаемыми тоже.
  Legacy — третий класс, конфликт разметки, не содержимого; следующая запись мигрирует сама.
  Все три класса видны и при нуле, чтобы отсутствие случаев не выглядело отсутствием понятия.
  Diff hand-edited строки вычисляется при scan; раскрытие не читает файл.
  Только этот класс имеет стратегию restore / save new version / skip:
  общую по batch с исключениями по строкам. Остальные объясняются и ведут в Place.
  Выбор сначала превращается в plan с результатами по месту.
  Для места сначала читаются сохраняемые правки и коммитятся версии Library,
  затем переписываются существующие копии. Restore/save повторно проверяют соседей под lock;
  новая неоднозначность отклоняется, файл без выбранного правила не меняется.
  Решение по строке разрешает отбросить лишь её правку, не skipped-правки остальных.
  Отказ одного места не откатывает успешные: для отката потребовалось бы вернуть ручной
  текст, которого после записи уже нет. После batch один scan, не scan на строку.
  По умолчанию ничего не выбрано: select all — явное действие перед возможной потерей правок.
- **⌘K:** общая навигация между Library objects, places и экранами в ranked list
  поверх окна, доступная с любого route, даже при фокусе в поле.
  Index — временный вид уже построенных catalog/place read-models, создаётся при открытии
  и удаляется при закрытии, без scan/собственного хранилища. Palette никогда не пишет,
  а выбирает объект Library или место.
  Ranking: точное имя → prefix → начало слова внутри имени → description.
  При равенстве редкие типы первыми: action, place, rule, skill, MCP, group.
  Одна буква и `:` ограничивает поиск (`r:`, `s:`, `m:`, `p:`) и исключает прочие виды/actions.
  Длинный `mcp:` остаётся обычным текстом: обрезание меняло бы введённый запрос.
  Пустой запрос показывает переходы, pinned/recent в порядке place list.
- **Клавиатура/layout:** chords принадлежат shell. ⌘K — palette; ⌘1–⌘4 — rail сверху вниз;
  ⌘, — Settings; Ctrl принимается везде вместо ⌘. Подсказки соответствуют macOS/Ctrl на остальных.
  Один preview pass в корне shell перехватывает их и при фокусе в поле.
  Они не пишут; ошибочная клавиша меняет лишь взгляд.
  Rail и pill ⌘K — Tab stops с видимым focus ring и Enter activation.
  Три колонки Place/Library адаптируются к окну: центр минимум 360 dp,
  боковые уменьшаются до 140 dp, затем исчезают начиная с ведущей.
  Список places/facets доступен через ⌘K/поиск, в отличие от trailing palette/inspector.
  Resize handle ограничен тем же правилом. В минимальном окне помещаются все три колонки.
  Сохраняется запрошенная ширина, не временно выданная узким окном.
  Window manager удерживает 900 × 600; меньший сохранённый frame увеличивается при загрузке:
  дальше уже нечего уменьшать без потери читаемости.
- **Settings:** машинные настройки с навигацией по одной секции:
  General (appearance, language, editor, workspace), Library (path, статистика repository,
  name format, внешний Git sync, import/export), Agents, read-only Shortcuts,
  About (version, diagnostics, paths).
  Контролы сохраняют сразу, без Apply. Одна agent table объединяет возможности
  Rules/MCP/Skills/Subagents, visibility и connection state.
  Настроенный library path сравнивается с открытым процессом: отличие до restart
  явно показано с возможностью отмены.

Ширины колонок и высота adoption pane — `columnWidths` в `config.json`;
размер/позиция окна — `window` в `config.json`, запись после завершения move/resize.
Restore вписывает frame в usable area подключённого монитора, сохраняя отрицательные
координаты. Отключённый монитор заменяется доступным; title bar остаётся достижимым,
даже если usable area меньше layout floor. Первый запуск занимает 70% usable area.
Name format (kebab/camel/snake/free) применяется при **каждом** сохранении имени
правила/группы, не только создании. Id не форматируется: это имя файла и ссылка групп/regions.
При возврате фокуса GUI перезагружает текущий data-owning route: MCP мог писать в фоне.

«Где установлено» — read-only scan, не путь записи. Один проход по configured places
читает каждый managed file один раз, спрашивает MCP/skill services и строит immutable
per-object index. Заодно получает regions, ownership, drift, ручные строки,
классификацию правок по библиотеке в памяти и доступность skill roots.
Home/Coverage выводятся из уже оплаченного Library scan, не обходят fleet повторно.
Чистый `@import` не предлагает adoption, как palette.
Place/Library используют общий `configuredTargets`, одинаковые места/включённых агентов.
Группа установлена там, где есть любой участник, с худшим его состоянием.
До первого scan index пуст; usage facets/counts скрыты, не объявляют всю библиотеку неиспользуемой.

Status dots place list читаются из того же scan. Открытие места читает лишь его файлы,
состояния и ручные остатки, не соседей. Их dots уже вычислены: иначе каждый переход
стоил бы полного обхода. До scan пустой dot означает «ещё не прочитано», не «синхронно».

Read scope живёт ровно scan: физический файл открывается один раз, parsed sidecars
и tree fingerprints вычисляются один раз, ответы переиспользуются внутри scope.
Scope read-only и per-thread; writer не открывает его и не пишет против устаревшего кеша.
Два scan не делят scope.

Place разделяет записи по контексту: palette устанавливает/удаляет объекты,
file preview обновляет существующий блок и отвечает на hand edit.
Palette не устанавливает поверх правки: выбор локального текста/Library принимается
там, где правка видна. Restore возвращает библиотечную версию; save new version
коммитит локальный текст; keep не меняет файл цели, сохраняет решение между restart,
пока точная копия не изменилась снова. Правило и MCP-entry могут стать Library-версией;
MCP читается из выбранного агента, у skill directory нет единого текста для adoption.
Установка не меняет порядок: существующий block обновляется на месте,
reorder — отдельная core-операция.
Adopt предлагается на найденном файле, не Library row, и первым пишет библиотеку.
Каждая запись повышает счётчик для повторного usage scan: reload исправляет выбранное
место, но агрегат «installed in 6 of 8» иначе остался бы старым.
Install/remove повышают его через model guard; adopt сообщает половинчатый сбой
(commit прошёл, target rewrite нет) и повышает счётчик при успехе любой половины.

Library bulk использует те же сервисы, без второго atomic write path и без force:
локальная правка, foreign MCP-entry, правило чужого проекта отклоняются и учитываются
в отчёте. Выбранная группа записывает участников с group tag; отдельно выбранный объект —
без tag, чтобы удаление группы не убрало самостоятельную установку.
Coverage удаляет через тот же путь по месту и защищает hand edit.
Только scope check при removal опускается: удаление сужает установку,
поэтому правило, установленное до привязки к проекту, должно оставаться удаляемым.

Диалог — вопрос либо рабочая поверхность. Вопрос подстраивается под содержимое;
splitter, file editor, adopt с секциями/переводом измеряются от окна и не меньше
70% ширины / 80% высоты (`workingDialogSize`), иначе две панели становятся нечитаемыми.

Тема — semantic tokens: Material colors/typography плюс Ruleblend colors,
dimensions, shapes, icons. Экран не выбирает light/dark сам.
`config.json.themeMode`: `SYSTEM`, `LIGHT`, `DARK`; SYSTEM следует desktop appearance,
явный режим меняет UI сразу.

Единая шкала статуса: conflict — красный, update — янтарный,
managed/synced — зелёный, ничего Ruleblend — серый.
Update — состояние содержимого с warning color ниже conflict;
синий `info` обозначает тип MCP, не sync state.
Составной dot показывает два самых приоритетных цвета слева/справа;
остальные остаются в tooltip: две половины читаются быстрее четырёх четвертей.
Зелёный ниже проблем, иначе почти любой настроенный place начинался бы зелёным.
Каждый установленный объект вносит один status; каждый файл без managed region — серый,
чтобы ненастроенное место не стало зелёным из-за отсутствия конфликтов.
У одного объекта dot одноцветный.

<a id="compare"></a>
## Compare

Единый JVM-движок — `core/compare`; Compose, Place, Resolve и version history — потребители.
`LineDiff` переводит UTF-8 в JGit `RawText` и строит hunks через `HistogramDiff`;
заменённые пары получают token diff `WordDiff`.
Hunk содержит соседние неизменённые строки и состояние последнего line break:
`HunkApply` переносит его в обе стороны даже после сдвига текста прошлым переносом.
Замена допустима только при совпадении anchored source range; исчезнувший из draft
диапазон отклоняется, не затирая hand edit.

Picker сравнивает лишь другие Library-объекты того же типа.
Similarity поровну учитывает Jaccard normalized words и character trigrams.
Первые пять scores идут в начало с округлёнными процентами; равные сохраняют catalog order,
как все оставшиеся кандидаты. Ranking лишь помогает выбрать объект, не меняет
adopt-решения `BlockMatcher`.

Pane открывается на diff. `sideBySideRows` выравнивает тексты по тем же hunks,
из которых построены transfer buttons: строка только одной стороны всё равно
занимает слот на другой. Одна scroll-column содержит left/gutter/right, удерживая
синхронность; строки wrap, не имеют независимого horizontal scroll.
Кнопки переноса только у первой строки hunk. Editing — другой режим segmented control,
с теми же drafts.

Тот же Compare используется file editor проекта: слева draft, справа любой файл
инструкций fleet, ранжированный так же. Pane не пишет на диск: перенос меняет draft,
а file editor решает о сохранении.

`ComparePane` создаёт два независимых временных draft из source/candidate.
Ввод, transfer/reset локальны; transfer/reset записывают пару drafts в общий undo stack.
Reset возвращает сторону к последнему сохранённому телу; оно же определяет наличие
изменений для save. Смена candidate заменяет лишь right draft и undo stack:
левый содержит работу пользователя, а undo всегда связывает обе стороны.
Отказ transfer оставляет оба draft как есть, не приводит к crash.
Git-импорты скиллов/субагентов read-only с обеих сторон.
Save редактируемой стороны использует обычное Library save и создаёт следующую версию;
закрытие ничего не сохраняет, отдельного постоянного формата Compare нет.

<a id="translation"></a>
## Перевод

Правила пишутся по-английски для агента и читаются человеком; редактор может показать
перевод рядом. Используется системный переводчик macOS 26.4+: offline, без поставляемой
модели, с language packs ОС и быстрым переводом абзацев. Запуск отдельного CLI-агента
на каждый абзац исключён из-за стоимости старта процесса.

- **`core/translate`** содержит `MarkdownSegmenter`, `AppleTranslator` с line protocol
  helper и управляющий процессом `HelperProcessChannel`.
  Узкий `Translator` позволяет добавить Windows/Linux backend позже по macOS-first стратегии.
- **Структура выделяется до перевода.** Системный переводчик принимает plain text,
  не Markdown: fences, indented code, tables, frontmatter, `<!-- rb1 -->` не отправляются.
  Inline code, URL, пути, link targets и CLI flags заменяются placeholders.
  Повреждённые placeholders возвращают исходный сегмент: непереведённый абзац безопаснее
  испорченной команды. Инвариант тестов — точный round-trip segment/reassemble без перевода.
- **Чтение парами.** Абзацы сопоставляются тем же segmenter, не вторым splitter:
  перевод собирается из исходной структуры. Если counts не совпали, весь текст
  показывается одной парой, не неверно сопряжёнными абзацами (`ParagraphPairs`).
- **Одна поверхность для всех экранов.** File preview, library editors и file dialogs
  используют общий `ParagraphSplit` с одним scroll.
  В редакторе открытый перевод — reading mode вместо поля: pairing на каждом символе
  сдвигался бы под глазами. Ввод возвращается через Hide translation.
  Сохраняются frame поля и accent fill managed block.
- **`rb-translate`** (`tools/translate-helper`, Swift) связывает с Translation framework.
  Долгоживущий процесс говорит NDJSON stdin/stdout и кеширует `TranslationSession`
  по языковой паре, поскольку её создание дорого. Stdout только для protocol,
  diagnostics в stderr. Gradle собирает helper, Compose кладёт в bundle;
  поиск через минимальный Finder `PATH` не нужен.
- **Language packs устанавливает пользователь.** Download требует UI `prepareTranslation`;
  headless helper лишь возвращает `packMissing`, а панель ведёт в System Settings.

<a id="export--import"></a>
## Экспорт / импорт

- Export — ZIP только переносимого layout библиотеки, без `.git`, вычисляемой `all`
  и посторонних файлов. История отделена от snapshot намеренно.
  Selective export включает выбранное; группа забирает участников,
  профиль — прямых участников, referenced groups и их участников,
  чтобы переносимый объект не импортировался с потерянными ссылками.
- Области правил не экспортируются: это локальные абсолютные пути.
  Новое импортированное правило глобальное; обновление существующего сохраняет его область.
- Merge по `id`: отсутствует → `new`, архивная версия выше → `update`,
  идентично → скрытое `same`, отличается без новой версии → `conflict`.
  До выбора ничего не пишется; `new`/`update` отмечены, `conflict` — нет.
- Блоки, группы, профили сохраняют архивную версию: auto-increment исказил бы импорт.
  Более высокая версия — update; иное отличающееся определение — конфликт,
  поскольку одинаковые версии с разными участниками не означают отставание одной стороны.
  `saveGroup` повышает версию локальной правки, `writeGroup` воспроизводит чужую ревизию.
- Полные каталоги скиллов и Git provenance переносимы.
  Executable-path metadata сохраняет executable scripts через ZIP;
  отличающиеся snapshots конфликтуют, поскольку opaque repository versions нельзя надёжно упорядочить.
- Разрешены только layouts `blocks/`, `groups/`, `profiles/`, проверенные `skills/<id>/`:
  ZIP не может писать вне библиотеки. Посторонний entry, дубликат пути, повреждённый ZIP
  отклоняют весь архив до записи. Пропускаются только Finder/Windows metadata
  `.DS_Store`, `__MACOSX/`, `Thumbs.db`, `desktop.ini` вне skill trees:
  старые экспорты включали их. Export/import разделяют layout, собственный ZIP всегда принимается.
  Id группы/профиля внутри YAML должен совпадать с filename: проверка лишь ZIP path
  не защищает destination, строящийся по внутреннему id.

<a id="mcp-server"></a>
## MCP-сервер

Агенты работают с библиотекой напрямую вместо ручного редактирования файлов инструкций.

- **Процесс:** packaged binary с `--mcp` (`Ruleblend.app/Contents/MacOS/Ruleblend --mcp`),
  один артефакт с приложением, не отдельный JAR; без packaging — wrapper ниже.
  Ветвление до AWT/Compose init, stdout только protocol, kotlin-logging banner подавлен,
  выход по stdin EOF. SDK `io.modelcontextprotocol:kotlin-sdk-server` 0.15.0.
- **Межпроцессная безопасность:** GUI/server могут писать одновременно.
  Advisory OS lock `~/.ruleblend/ruleblend.lock`, reentrant с timeout 10 s,
  берётся внешним `LibraryGit.withLock` и `ConfigStore.update`.
  Чтение без lock: repository перечитывает диск на вызов, запись атомарна.
- **Tools:** полный публичный каталог и workflow — во
  [встроенном скилле](../../mcp/src/jvmMain/resources/dev/ruleblend/mcp/skill/SKILL.md#tools).
  Установка профиля привязывает/включает, удаление выключает/отсоединяет через
  `ReconcileProfiles`. Строки MCP, субагентов, скиллов имеют `kind`;
  правила берутся из managed regions.
  `create_subagent`/`update_subagent` хранят переносимое определение и per-assistant
  `variants` по id; shortcut `model` применяется ко всем поддерживающим субагентов ассистентам.
  MCP создаёт локальные скиллы и редактирует полные деревья через library mutation use case.
  File edit держит lock через read/validation/atomic replacement, защищая от lost update.
  Revisions покрывают байты и executable intent; идентичная запись — no-op.
  Чтение strict UTF-8 или Base64; общие capture/storage limits — 500 файлов,
  10 MiB на файл, 25 MiB всего, переносимые пути, без Git bookkeeping/symlinks.
  `SKILL.md` обязателен, name/description frontmatter поддерживаются автоматически.
  Git-импорты неизменяемы. Удаление скилла/субагента убирает членство групп/профилей,
  оставляя установленные копии до явного uninstall.
  Install/remove используют общий `SubagentInstallService`, byte ownership и drift checks.
  Result отдельно называет written, modified, unsupported; ZCode/Pi без fallback-пути.
  `RuleblendTools` — чистые handlers поверх `core`, без SDK types, тестируются без транспорта.
- **Цели:** `target` — `agent:<agentId>` для globals или абсолютный project path,
  те же два вида GUI через общий `Target`, без отдельной install logic сервера.
  `project_path` принимается как прежнее имя до 1.11.
  Id агента разрешается лишь среди available/non-hidden; неизвестный возвращает список доступных.
  Registration и switches работают без включённых агентов, меняют только local config.
  Unregister забывает bindings/navigation даже missing checkout, не удаляет файлы/Library.
  Hidden/unavailable ассистенты сохраняют switches при смене видимого enabled set.
- **Git через MCP:** previews хранят ограниченные core import plans в сессии по opaque id.
  Два snapshots, срок десять минут. Apply использует проверенные байты, не новый moving HEAD.
  Entry read отдельно показывает исходник/трактовки ассистентов, не перегружая discovery list.
  Apply, source update, forks используют общие GUI use cases.
  Check сохраняет существующий disposable cache; source list выводится из provenance.
  List/get дают полное происхождение/editability и прежнюю строку skill `source`.
  Validation отклоняет весь выбор до записи; storage failure сохраняет уже committed objects,
  атомарно откатывая ошибочный объект, не весь batch.
  После fetch update повторно проверяет выбранные определения под lock,
  защищая объекты, удалённые/заменённые параллельно.
- **ZIP/history через MCP:** два reviewed import snapshots на десять минут, как Git previews.
  Apply проверяет весь выбор и перечитывает local definitions под lock,
  не позволяя старому preview заменить concurrent edit. Байты архива захвачены заранее.
  Export использует общий dependency closure и atomic guarded replacement вне активной библиотеки.
  History ищет по object paths, включая удалённые объекты.
  MCP-config patches скрываются по полным документам обеих сторон коммита:
  неизменённый type header может не попасть в diff context.
  Archive preview bodies защищены так же. Exported ZIP намеренно сохраняет исходные
  credentials и требует запрошенного destination.
- **Remote библиотеки через MCP:** status читает local state без fetch.
  Sync требует явного подтверждения и использует существующий merge/push service
  с typed conflicts/unrelated-history reports. Remote URL/raw Git messages скрыты:
  оба могут содержать credentials. Setup/replacement remote и влияющие на сессию
  settings остаются в GUI; bundled skill описывает coverage и причины desktop-only операций.
- **Установленные копии через MCP:** общая с Place native classification/rule scan,
  выбор physical entry keys, не произвольных file paths.
  Read даёт installed/Library content и file-level differences skill trees.
  Write повторно проверяет revision ownership и обоих contents под lock,
  затем вызывает target services: просмотренная копия не становится другой mutation незаметно.
  Local acceptance только для правил/MCP, как Place. Foreign rules по умолчанию копируются;
  replace требует явного подтверждения, referenced files остаются copy-only.
  Правило наследует область выбранного проекта.
  Native adoption записывает ownership без rewrite; сбой удаляет новый Library object.
  Rule replacement может оставить committed Library rule при сбое target write.
  Release/orphan removal действует по id во всей цели; modified orphans отклоняются.
  Foreign deletion только явно подтверждённых skills/MCP, сохраняя соседний config.
  Built-in integrations вне этих tools.
- **Server instructions** initialize остаются указателем: hosts вставляют их в каждый
  system prompt. Workflow находится в skill/tool descriptions; последние доступны и агентам без skills.
- **Install:** только абсолютные существующие пути; неизвестный проект auto-register для GUI.
  Target строится как в GUI; project-scoped rule отклоняется вне проекта.
  Modified regions/skill trees пропускаются с отчётом, кроме `overwrite: true`.
  Группа включает все поддержанные типы участников. Agent targets не регистрируются:
  существуют, пока доступен агент.
- **Connect to MCP в Settings:** одно действие записывает обе части подключения.
  `McpConnector` создаёт `ruleblend`: structural JSON в `~/.claude.json`,
  line-based section в `~/.codex/config.toml`, native JSON `$KIMI_CODE_HOME/mcp.json`,
  compatible JSON `~/.agents/mcp.json` ZCode, `$PI_CODING_AGENT_DIR/mcp.json` Pi
  (по умолчанию `~/.pi/agent/mcp.json`).
  Прямая запись надёжнее agent CLI при минимальном GUI PATH.
  Совпавшее имя writable лишь с Ruleblend version stamp или старым unversioned
  app-bundle/dev-wrapper path с `--mcp`; иное foreign, Connect/Disconnect его не меняют.
- **`McpLauncher`:** установленный binary через `jpackage.app-path` либо dev-launcher
  в `~/.ruleblend/bin/`, всегда с `--mcp`.
  POSIX — `ruleblend-mcp`; Windows — `ruleblend-mcp.exe` из GUI jpackage launcher текущего JDK.
  Windows dev требует полный JDK с `jdk.jpackage.jmod` и Windows PowerShell;
  preparation failure показывается в Settings.
  Путь стабилен между rebuild; переход dev/installed требует reconnect.
  Content stamp не заменяет running Windows executable.
  Classpaths — URI-encoded content-addressed JAR manifests в `bin/app/`;
  atomic `.cfg` направляет новые процессы на текущий classpath, не заменяя открытые JAR старых сессий.
  Dev/packaged Windows launcher объявляют
  [UTF-8 process code page](https://learn.microsoft.com/en-us/windows/apps/design/globalizing/use-utf8-code-page)
  (Windows 10 1903+): default ANSI Java иначе теряет кириллические пути на нерусской Windows.
  GUI-subsystem executable сохраняет inherited stdio без консольного окна.
- **Встроенный скилл:** `FileSkillInstaller` пишет resource `SKILL.md` в native user roots:
  `~/.claude/skills/ruleblend/SKILL.md`, `~/.codex/skills/ruleblend/SKILL.md`,
  `~/.agents/skills/ruleblend/SKILL.md` Pi, `$KIMI_CODE_HOME/skills/ruleblend/SKILL.md`,
  `~/.zcode/skills/ruleblend/SKILL.md`. Текст/marker ownership общие;
  каждый installer определяет availability/path. Это не Library block: пользователь
  не редактирует/удаляет его там, app update заменяет on-disk copy.
  Последняя строка ownership comment задаёт not installed, installed (совпадает),
  outdated (наша старая копия), foreign (нет marker, не трогаем).
  MCP-строка connected лишь при совпадении registration и skill.
- **Версии установленных артефактов:** skill и MCP entry сами сообщают версию,
  чтобы stale state определялся и после потери sidecar.
  Skill использует `<!-- ruleblend-managed skill v1 -->`, MCP env — `RULEBLEND_ENTRY`,
  читаемый во всех форматах. Обе версии повышаются вручную:
  skill — при смене `SKILL.md` (digest test привязывает текст к номеру),
  `MCP_ENTRY_VERSION` — при изменении создаваемой регистрации.
  Они не следуют app version, иначе каждый релиз без причины объявлял бы всех stale.
  Старая unversioned copy — v0, однократно исправляется после update.
  `BundledIntegration` единственный reader/writer repair; Home attention card
  и Settings предлагают обновить одного/всех ассистентов. Foreign skill виден, но не переписывается.
- **Оба артефакта в Library:** built-in skill/MCP с reserved `builtin:skill`, `builtin:mcp`;
  `:` не входит в slug, Library не займёт эти id.
  Только имя, версия, описание, полный текст: без editor/delete/bulk checkbox/usage/source facets.
  Установка из Settings.
- **Оба артефакта в Projects:** ownership markers распознают их в Skills/MCP.
  Они считаются managed, definition читается; Place не даёт edit/adopt/hide/remove.
  Обновление/удаление только в Settings.

<a id="mcp-blocks"></a>
## MCP-блоки

Блок `type: mcp` описывает сторонний сервер для установки в MCP-config агентов.

- **Канонический config (`McpServerConfig`):** JSON с discriminator `transport`:
  `stdio` (`command`, `args`, `env`) или `http` (`url`, `headers`).
  `McpConfigCodec` разбирает/стабильно сериализует байты, не вызывая лишних version bumps.
  Ключ server entry — block id; `ruleblend` зарезервирован для self-registration.
- **Редактор:** только structured form. Неразбираемое тело — read-only плюс reset;
  invalid config запрещает Save.

  | Агент | Глобально | Проект |
  |---|---|---|
  | Claude Code | `~/.claude.json` `mcpServers` | `<dir>/.mcp.json` `mcpServers` |
  | Codex | `~/.codex/config.toml` `[mcp_servers.<id>]` | `<dir>/.codex/config.toml` (только trusted projects) |
  | Kimi Code | `<KIMI_CODE_HOME>/mcp.json` `mcpServers` | `<dir>/.kimi-code/mcp.json` `mcpServers` |
  | ZCode | `~/.agents/mcp.json` `mcpServers` | `<dir>/.mcp.json` `mcpServers` |
  | Pi 1.0+ | `~/.pi/agent/mcp.json` `mcpServers` | `<dir>/.pi/mcp.json` `mcpServers` (требуется доверие к проекту) |

  Claude JSON явно пишет `"type"`. Kimi определяет transport по `command`/`url`,
  поэтому `KimiMcpJson` не добавляет `type`/другой discriminator.
  Его проектный адрес — native `<cwd>/.kimi-code/mcp.json`, представленный project target.
  Отдельный `<project>/.mcp.json` — shared Claude-compatible layer, читаемый ZCode
  как project compatibility config. Глобальный shared ZCode использует тот же JSON
  с явным transport. Codex пишет stdio как `command`, `args`, `env`, streamable HTTP —
  `url`, static `http_headers` в одной named table.
  Pi различает `command`/`url`, игнорирует Claude `"type"`, поэтому разделяет Claude JSON writer.
  Pure helpers `McpServersJson` / `KimiMcpJson` / `CodexMcpTable` сохраняют чужое содержимое.
- **State:** у config нет переносимых комментариев для markers.
  `~/.ruleblend/mcp-state.json` хранит version/config по `(targetKey, agentId, blockId)`.
  При наличии записи: совпадает с Library render → `synced`;
  совпадает с записанным render, но Library изменилась → `update available`;
  иначе `modified`.
- **Ownership:** одноимённая запись без sidecar чужая независимо от содержимого,
  перезаписывается лишь при явном подтверждении, пропускается group-операциями.
  Потеря state превращает записи в foreign, не в управляемые по совпадению.
- **Группы** не зависят от типа. Origin MCP-участника хранится в sidecar, не agent config.
  Удаление группы берёт лишь копии её origin, самостоятельные сохраняют свой.
  Старые builds не оставляли origin: до 165 для MCP/skill/subagent,
  до 169 при индивидуальном update любого участника.
  Такие копии неотличимы от самостоятельных, миграция не может переименовать origin.
  Remove перечисляет сохранённых без origin участников всех видов и удаляет
  лишь при втором явном подтверждении; по умолчанию сохраняет.
  Неподдержанные всеми агентами цели участники исключаются из group check.
- **Self-registration Ruleblend** — disabled status row над Library MCP.
  Читаются глобальные подключения применимых агентов; install/remove остаются в Settings.

## Надёжность и тестирование

Root UI suite — opt-in, отдельная JVM compilation, не Kotlin test run:
aggregate test tasks не обнаруживают его. Каждый cold start — новая JVM с home/child
окружением до загрузки static paths, сохраняя production service graph и lifetime lock.
Подменяются лишь OS actions/translation. Guard JDK 17 отклоняет запись вне canonical
fixture root и symlink escapes; native macOS prototype использует OS sandbox.
AX references сохраняют PID: поиск по имени может попасть в другую копию приложения.
ffmpeg снимает/crop-ит native frame без аудио.
Report требует реальных testcase и успешного process exit; skipped/blocked prerequisites
не считаются приёмкой. Запуск/артефакты — в [UI E2E](UI_E2E.md).

- Каждый пользовательский файл пишется атомарно: temp + rename.
- Atomic rename ограниченно повторяет transient Windows sharing violations,
  включая home migration, library replacement, skills.
  Unsupported atomic move, отсутствующий source, занятый destination сразу дают ошибку:
  удаление оригинала/copy-over показали бы неполные данные.
  Persistent lock сообщает source/destination.
  Failed skill restore сохраняет rollback directory; следующий replacement не перезапишет его.
  Общий process lock ограничивает thread waits, не только OS lock waits.
  Guarded write повторно проверяет файл перед каждым retry, сохраняя внешнюю правку.
- Atomic rename исключает half-written file, но не lost update двух read-modify-write.
  Такие циклы для target files, agent MCP config и sidecar выполняются через
  `TargetMutationCoordinator` под общим `ruleblend.lock` библиотеки/config.
  Writers одного/двух процессов сериализованы; whole-target lock от первого read
  до последнего write не позволяет cooperating writers перемешать обновление цели.
  Lock-free readers всё ещё могут увидеть промежуточные файлы multi-file write.
  Advisory lock не охватывает внешний editor: перед rename повторно сравниваются
  размер/content digest прочитанного файла. При изменении цикл пересчитывается
  по новому тексту, сохраняя правку снаружи и отклоняя drift внутри managed region.
  После трёх пересчётов запись прекращается, не форсируется.
  Skill tree fingerprint повторно проверяется между preflight и первой правкой каталога.
- Mutation включает файл и производную запись под одним lock:
  target + `targets.index`, MCP + `mcp-state.json`, skill + `skill-state.json`.
  Запись не должна описывать уже изменившийся файл.
  Stores перечислены вместе с файлами; один state/index содержит все targets,
  поэтому два разных target всё равно делят его read-modify-write.
- Unit tests рядом с кодом всех трёх модулей. Покрыты основные риски:
  marker round-trip обоих encodings, ownership detection/migration, import merge,
  adopt extraction/matching, Move round-trip, splitter, MCP codec/config editors,
  install status matrix.
- Gate запускает `:core:allTests :mcp:allTests :app:allTests`:
  тест фасада/экрана бесполезен, если CI запускает лишь core.
  Gate/runner contracts выполняются macOS/Windows: Gradle daemon JDK 21,
  app/test toolchain JDK 17. Native UI/translation acceptance — opt-in.
- Text resources фиксируют LF через `.gitattributes`: checkout setting не меняет bytes/version.
  Bundled skill digest проверяет реальный resource без normalization.
- Integration tests охватывают прежние обходы ownership migration:
  fresh install, legacy conversion on install, redirect sync, adopt/remove.
- Whole-target write — одна операция. До последовательной записи файлов разных
  агентов снимаются snapshots всех; failure откатывает уже изменённые.
  Per-file result: written, unchanged, failed, rolled back, stranded при failed undo.
  Pointer входит в набор: failure pointer откатывает rule files.
  MCP/skills используют свои snapshots с тем же правилом.
  Stranded file назван в ошибке, не считается откатанным.
  При частичном успехе group/bundle report показывает written/refused/failed
  рядом с первой ошибкой, не только её текст.
- Идентичность проекта одна: абсолютный нормализованный путь.
  Registration, profile bindings, disabled agents, rule scopes, sets/pins и MCP records
  используют её; config read исправляет прежние написания вместо дублирования checkout.
- Config/sidecar reads деградируют безопасно. Неразбираемый config переносится в
  `config.json.broken`, приложение стартует с defaults и один раз сообщает путь.
  Нечитаемый backup index теряет список, не snapshots.
  Unknown fields/enum values обрабатываются decoder как forward compatibility, не corruption.
- Place refresh ограничен read budget, не секундомером:
  пятьдесят правил открывают каждый файл один раз; повторное чтение ломает тест.
- Compiler warnings запрещены в CI (`-PwarningsAsErrors=true`), локально лишь предупреждают:
  обычно это код, который будущий Kotlin откажется компилировать.
- Unit gate детерминирован, не зависит от машины.
  Тесты с macOS Translation framework, собранным `rb-translate` и language pack
  называются `*MacOsIntegrationTest`, исключены из `jvmTest`, запускаются через
  `:core:macOsIntegrationTest`. Missing prerequisite — skipped, не passed:
  зелёный gate не означает непроверенную интеграцию.
  Общий протокол — ids, timeouts, один retry, error mapping — проверяется
  scripted `TranslateChannel` внутри gate.
