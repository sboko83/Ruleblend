# Сквозные проверки интерфейса

[English version](../UI_E2E.md)

Наборы запускаются вручную. Они не входят в `test`, `jvmTest`, `allTests`, `check`,
упаковку, CI и `tools/verify_ui.sh --all`. Список доступных наборов — `tools/verify_e2e.sh --list`.

Все команды выполняются из корня репозитория.

Единый выбор набора или сценария:

Python 3.12+; для сборки Gradle нужен JDK 21, тестовые JVM используют toolchain 17.
На Windows вместо `tools/verify_e2e.sh` используется `python tools/verify_e2e.py` с теми же
аргументами. Для проверок symlink нужны Developer Mode или право создания символических ссылок;
их отсутствие считается ошибкой предусловий, тесты не исключаются из набора.
`desktop`, `translation-live` и N-11 используют macOS sandbox и на Windows возвращают `blocked`.
Контракты runner без UI входят в CI; графические сценарии запускаются только вручную.

```sh
tools/verify_e2e.sh --list
tools/verify_e2e.sh smoke
tools/verify_e2e.sh library ownership profiles coverage
tools/verify_e2e.sh exchange sources sync
tools/verify_e2e.sh translation settings recovery
tools/verify_e2e.sh --all-local
tools/verify_e2e.sh --scenario R03
RULEBLEND_E2E_BUNDLE=/absolute/path/Ruleblend.app tools/verify_e2e.sh desktop
```

`--all-local` запускает только детерминированные UI-наборы. `desktop` и
`translation-live` требуют заранее собранный `.app` и отдельный явный запуск.
Каждый набор сохраняет собственный отчёт; ошибка одного не отменяет следующие запрошенные наборы,
а общий код выхода сохраняет ошибку или blocked/skipped. Повтор по ID создаёт новый корень и
сохраняет отчёт предыдущего запуска.

```sh
# Корневой UI и холодный перезапуск в новой JVM, один временный корень.
python3 -B tools/ui_e2e.py ui
python3 -B tools/ui_e2e.py ui --tests '*RootSmokeTest*' --timeout 240

# Фаза 1: каждый сценарий P-01…P-12 на собственном временном корне.
python3 -B tools/ui_e2e.py projects
python3 -B tools/ui_e2e.py projects --tests P08

# Фаза 2: каждый сценарий L-01…L-12 на собственном временном корне.
python3 -B tools/ui_e2e.py library
python3 -B tools/ui_e2e.py library --tests L08

# Фаза 3: каждый сценарий O-01…O-12 на собственном временном корне.
python3 -B tools/ui_e2e.py conflicts
python3 -B tools/ui_e2e.py conflicts --tests O01

# Фаза 4: каждый сценарий G-01…G-09 на собственном временном корне.
python3 -B tools/ui_e2e.py groups
python3 -B tools/ui_e2e.py groups --tests G07

# Фаза 5: каждый сценарий F-01…F-09 на собственном временном корне.
python3 -B tools/ui_e2e.py overview
python3 -B tools/ui_e2e.py overview --tests F07

# Фаза 6: архивы X-01…X-05 и Git-навыки S-01…S-05.
python3 -B tools/ui_e2e.py archives
python3 -B tools/ui_e2e.py archives --tests X01
python3 -B tools/ui_e2e.py git-skills
python3 -B tools/ui_e2e.py git-skills --tests S03

# Фаза 7: двусторонняя Git-синхронизация библиотеки Y-01…Y-10.
python3 -B tools/ui_e2e.py git-sync
python3 -B tools/ui_e2e.py git-sync --tests Y03

# Фаза 8: перевод через корневой UI с управляемым ответом T-01…T-07.
python3 -B tools/ui_e2e.py translation
python3 -B tools/ui_e2e.py translation --tests T05

# Фаза 9: настройки и подключения N-01…N-07, N-11 без нативного окна.
python3 -B tools/ui_e2e.py settings
python3 -B tools/ui_e2e.py settings --tests N05

# Фаза 10: восстановление R-01…R-06, включая контракт отчёта R-05.
python3 -B tools/ui_e2e.py recovery
python3 -B tools/ui_e2e.py recovery --tests R01

# Фаза 8: собранное окно и упакованный macOS helper T-08…T-09.
./gradlew :app:createDistributable
python3 -B tools/ui_e2e.py translation-live --bundle app/build/compose/binaries/main/app/Ruleblend.app
python3 -B tools/ui_e2e.py translation-live --tests T09 --bundle app/build/compose/binaries/main/app/Ruleblend.app

# Общий smoke: основной путь P-07 с холодным перезапуском.
python3 -B tools/ui_e2e.py smoke

# Удалить все завершённые стенды во временной папке; незавершённые остаются.
python3 -B tools/ui_e2e.py cleanup

# Контракты отчёта, таймаута и очистки, без UI.
python3 -B -m unittest discover -s tools -p test_ui_e2e.py

# Настоящее окно macOS: ffmpeg, Accessibility, Automation для System Events и запись экрана.
./gradlew :app:createDistributable
python3 -B tools/ui_e2e.py desktop --bundle app/build/compose/binaries/main/app/Ruleblend.app
python3 -B tools/ui_e2e.py desktop --tests N09 --bundle app/build/compose/binaries/main/app/Ruleblend.app
```

UI-набор использует Compose JUnit v2, корневой интерфейс приложения и настоящие файловые сервисы.
Подменяются выбор папки/архива/редактора, обнаружение CLI, внешние приложения и перевод.
Это не проверка системного диалога или настоящего перевода. Каждый старт работает в новой JVM 17:
home и окружение задаются до загрузки классов; все JVM-записи ограничены каноническим корнем,
внешние процессы и сеть запрещены. Обычный запуск приложения не устанавливает этот контроль.
`ui` по умолчанию сохраняет набор стенда фазы 0; `smoke` выполняет P-07, а `projects` запускает
P-01…P-12 по одному на отдельных корнях. P-03, P-07 и P-10 проверяют холодный перезапуск.
`conflicts` запускает O-01…O-12 по одному на отдельных корнях; внешние правки и ошибочные файлы
создаёт только фикстура внутри этого корня.
`library` запускает L-01…L-12 по одному на отдельных корнях; локальный Git-источник L-10
готовится внутри стенда до запуска приложения.
`groups` запускает G-01…G-09 по одному на отдельных корнях; G-07 дополнительно
проверяет config и привязки после холодного перезапуска.
`overview` запускает F-01…F-09 по одному на отдельных корнях и проверяет
Главную, Покрытие и Resolve через корневой интерфейс и реальные файлы. F-09
дополнительно проверяет настройки после холодного перезапуска.
`archives` запускает X-01…X-05 по одному; X-01 и X-02 переносят ZIP в пустую
библиотеку и конфигурацию следующего процесса. `git-skills` запускает S-01…S-05
с локальным Git-источником; S-03…S-05 меняют фикстуру между процессами, а S-05
проверяет ручной и автоматический режимы на отдельных холодных запусках.
`git-sync` запускает Y-01…Y-10 по одному с локальным bare remote и вторым
клиентом внутри стенда; Y-09 и Y-10 проверяют состояние после холодного старта.
`translation` запускает T-01…T-07 на отдельных корневых UI-стендах с управляемым
переводчиком; T-02 проверяет установленное правило в файле проекта, T-05 — переводчиком,
который портит всё незамаскированное. `translation-live`
запускает собранное приложение через Accessibility и его упакованный helper, проверяет
языковые пакеты EN→RU и RU→EN перед запуском и не устанавливает их. T-09 дважды
открывает приложение в отдельных процессах. Отсутствующий пакет даёт `blocked`.
`settings` запускает N-01…N-07 и N-11 отдельно; N-11 перед стартом собирает текущий
дистрибутив для второго процесса `--mcp`. N-01, N-02, N-04 и N-05 используют холодный
перезапуск. `desktop` запускает H-08 и N-08…N-11 по одному в настоящем окне.
N-08 выбирает экспортированный ZIP после холодного перезапуска приложения.
`recovery` запускает R-01…R-06; R-01 и R-06 проверяют холодный перезапуск, R-01 — ещё и
пропавшую папку проекта. R-03 дважды прогоняет smoke P-07 на новых чистых корнях и сверяет
отпечаток реального home. R-02 принудительно завершает вторую JVM посреди атомарной перезаписи
правила, удерживает lock вторым процессом и проверяет отказ записи через UI. R-05 проверяет
семантику отчётов на синтетических исходах без запуска Compose; его первая неудачная
фикстура сохраняется для осмотра до `cleanup`.

Desktop-набор запускает упакованный бинарник под macOS sandbox, ограничивающим записи
и дочерние процессы тем же корнем. Перед запуском проверяется отказ записи наружу, после —
отпечатки рабочих конфигураций и установленных файлов ассистентов. Журналы чужих сессий и кеши
в отпечатки не входят. Драйвер использует Accessibility через `osascript`; автоматизированы
запуск, системный выбор папки, клавиатурный ввод, снимок окна и штатное закрытие.
N-08…N-11 отдельно проверяют системные диалоги, размер и восстановление окна, About и
обновление после внешней записи через MCP. `ffmpeg` через AVFoundation сохраняет кадр без звука,
обрезанный по границам окна с учётом масштаба Retina. Окно должно целиком находиться на основном
дисплее; работа с несколькими мониторами этим набором не покрывается.
Недоступное разрешение или отсутствующий `ffmpeg` дают `blocked`; доступ к System Events требует
разрешения «Автоматизация», а снимок — «Запись экрана» для запускающего приложения.
Неоднозначный элемент, ошибка драйвера и таймаут дают `failed`.
Ссылки на элементы сохраняют PID: несколько запущенных копий Ruleblend могут иметь одинаковое имя.

Код выхода: `0` — все выбранные сценарии прошли; `1` — ошибка/таймаут/пустой набор;
`3` — есть skipped или blocked. Успешные XML не отменяют ошибку Gradle.
Отчёт и снимки сохраняются в `build/ui-e2e/<run>/`. При ошибке остаётся также временный
sandbox с логами, XML, реальными файлами и манифестом; путь выводится в терминал.
Успешный sandbox удаляется после завершения процессов. Очистка сохранённого стенда:

```sh
python3 -B tools/ui_e2e.py cleanup /private/tmp/ruleblend-e2e-<run>
```

Очистка требует собственного маркера и не следует по символическим ссылкам.
Прямую Gradle-задачу `:app:uiE2e` использует runner; ей требуется подготовленный
`-Pe2eRoot=...`, а `-Pe2eStage=...` выбирает этап. Для компиляции без прогона:
`./gradlew :app:compileUiE2eKotlinJvm`.

## Сопровождение сценариев

- Пользовательские действия выполняются через корневой UI; прямой вызов модели не заменяет клик.
  Фикстура готовит окружение, внешние правки и ошибки только внутри изолированного корня.
- Сценарий проверяет видимый результат и независимо читает файлы/config/sidecar;
  проверка сохранённого состояния при необходимости включает холодный перезапуск.
- Селекторы опираются на устойчивые id, тип, место и действие; нативные — на доступные имена и роли.
  Ожидания ограничены таймаутом и проверяют нужное состояние: Compose-idle не означает конец I/O.
- Git-сценарии используют локальные репозитории. Обычные наборы подменяют CLI и перевод;
  настоящий диалог, дистрибутив и перевод проверяются отдельными нативными наборами.
- После прогона `python3 -B tools/ui_e2e.py cleanup` удаляет завершённые временные стенды,
  включая оставшиеся после ошибок. Незавершённые и чужие каталоги остаются; отчёты в `build/ui-e2e`
  сохраняются. Перед очисткой нужные для разбора артефакты следует сохранить.
